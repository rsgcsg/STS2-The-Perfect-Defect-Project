# P1 环境协议（草案，目标修订 r1）

状态：草案。r1 在调查任务 C 的逐场景事实补齐、两端映射表通过独立审查后定稿；定稿前，依赖 P1 输入的数据、训练和评测都不开始。
上级：[SYSTEM_MAP 第 3 节](../SYSTEM_MAP.zh-CN.md#3-环境协议p1)。当前选定组合见[活动计划](../plans/P1_ROUND1_PLAN_2026-10-14.zh-CN.md)。

名称：本文的 P1 只指**环境协议**。历史任务表里的"P1（现状审计）"和组合启动的"P1-A/B 实施包"是别的东西，保留原 ID，不混用。
P1 按修订号演进（r1、r2…），名字不变；每个修订号对应一份完整的 Agent 面、Host 面映射和一致性检查。

## 1. 一套协议包含什么

```text
Host（Reference 或 Managed） ←[P1-H：向 Host 取什么、怎么交互]→ P1 适配器 ←[P1-A：Agent 看什么、做什么]→ Agent
```

| 部分 | 内容 | 对谁统一 |
| --- | --- | --- |
| P1-A（Agent 面） | 观察里有什么、动作目录、每步反馈、一局的开始和结束、缺失与失败怎么表达 | 所有 Host、所有 Agent 相同 |
| P1-H（Host 面） | 适配器从 Host 取哪些事实、用什么接口取、怎么下发动作、怎么拿回执 | 每种 Host 一份实现 |
| 适配器 | 组装 P1-A 观察；下发动作；检查完整性与一致性；处理等待和失败 | 每种 Host 一个，行为必须符合 P1-A |

Agent 只认识 P1-A。Read、snapshot、lease 等是 P1-H 和适配器内部的事。内部的 Read、传输、模型 Input、录制格式仍各有版本化合同，
它们不叫"环境协议"，但不能因此省略。

**同一个 `sts2.dll` 不保证两个 Host 行为相同。** Managed 在 TestMode 下运行游戏代码，带手工投影和若干运行补丁
（见 `components/host-runtime/experiments/managed-exact/manifest.json`）；历史成对运行已经出现过效果时点不同的分叉。
两个 Host 在 P1 下是否一致，只能按 [SYSTEM_MAP 第 5 节](../SYSTEM_MAP.zh-CN.md#5-改哪一层以及两个-host-怎样比较) 在声明的范围内成对检查。

## 2. 设计原则

1. **信息**：给出玩家此刻在原生界面上**能看到、且查看不产生效果**的全部信息。判断标准是"原生此刻是否可见、打开是否有效果或改变机会"，
   不是"内部对象是否已经存在"：内容可能已由 RNG 预先生成但尚未揭示，这种内容不给。
2. **可得性分状态**：每个字段区分 可得 / 本页面正常不可得 / 未知 / 不支持 / 结算中 / 终局，不用同一个"缺失"。
3. **动作**：保留游戏真实的选择阶段（选牌→目标→确认/取消；奖励的打开/领取/离开；卡牌奖励的选择/跳过/返回），只省略滚动、坐标、悬停。
   Managed 的文本菜单本地光标移动不是原生 Commit，回执要分开表达。
4. **时机**：只在稳定决策点调用 Agent；等待、动画、结算由适配器处理。终局时返回空目录和终局信息，不等待非空目录。
5. **一致包**：一份观察里的所有事实来自同一时点。多个 Read 共用同一 snapshot ID 是必要条件，不是充分条件；
   适配器要按现有 owner 封存一致的包，或证明相关字段在取数期间未变。合法详情不截断（例如多个 surface_card 实例）；超出上限就拒绝并报告。
6. **完整才发布**：必需字段缺一项，这次观察不发布，适配器报告缺什么；不给半个观察，也不悄悄降低"必需"的含义。
7. **不加提示**：不放程序推导的访问计数、推荐、步数。区分"第一次来"和"重访"是 Agent 记忆的事。
8. **公平**：隐藏 RNG、真实抽牌顺序、未揭示的奖励永不进观察；公共 ID、别名和摘要也不能间接编码它们
   （例如内部计数、原 index、含隐藏排列的 hash）。验收含置换不变性反例。

P1 不保证马尔可夫：同一个观察可以出现两次而需要不同决定，所以默认 Agent 要有记忆。

## 3. P1-A：观察

每个决策点一份观察文档（schema 名在 r1 定稿时确定）。字段分"模型可见"和"信封"两类，信封只用于绑定与去重，不进模型。

| 部分 | 内容 | 何时出现（r1 前由任务 C 核实） |
| --- | --- | --- |
| `run` | 角色、进阶、幕、层、Boss、修饰、HP/最大 HP、金币 | 总是 |
| `deck` | 牌组（多重集），每张：definition_id、名称、升级、费用、描述文本、数值字段 | 总是 |
| `relics` / `potions` | definition_id、名称、描述、计数器；药水槽上限 | 总是 |
| `map` | 本幕地图：节点类型、连线、当前位置、已走路径 | 待核：是否任何页面都可查看 |
| `screen` | 当前决策页面的全部可见内容（奖励列表、事件文字与选项、商店货架、营火选项、选择器候选与已选状态等） | 总是 |
| `combat` | 回合、能量、玩家格挡/能力/充能球/姿态；手牌（当前费用、可否打出）；抽牌堆（无序多重集）、弃牌堆、消耗堆；敌人（HP、格挡、能力、意图与数值） | 战斗中 |
| `availability` | 每个可缺字段的可得性状态（原则 2） | 总是 |
| 信封 | observation_id、episode_id、occurrence 序号、动作绑定 ID、Host 与游戏版本 | 总是，不进模型 |

## 4. P1-A：动作、反馈、记忆推进和一局的边界

- **动作目录**：当前决策点全部合法动作；每个有动词、引用参数、可读标签、信封里的绑定 ID。目录由游戏/Connector 产生，适配器和 Agent 不增删。
- **一步**：Agent 选一个动作 → 适配器下发 → 回执 `delivered` / `not_delivered` / `unknown`，以及下一个稳定观察。
  `not_delivered`（状态已变）时给新观察让 Agent 重选；`unknown` 时本局以删失结束，不重试。
- **记忆推进**（信封中的 occurrence 决定，模型看不到这个计数）：
  - 同一次观察因传输或过期被重新取回：不推进。
  - 状态确实变化后得到的新观察：推进一次。
  - 经过中间页面又回到内容相同的页面：是新的发生，推进。
- **一局**：由任务（角色、进阶、种子）开始，到胜/负终局结束；超步数、超时、unknown、不完整观察算删失并记录原因。开局、种子、重开属于任务管理。

## 5. P1-H：各 Host 怎么实现

| Host | 取事实 | 下发动作 | r1 前要核实 |
| --- | --- | --- | --- |
| Reference（真实游戏 + Mod） | Connector `snapshot-1` + 当前声明的全部 Reads（含 `surface_card`），按原则 5 组成一致包 | Connector actions + receipts，执行前复验 | surface_card 多实例与上限；一致包的封存方式；地图在非地图页 |
| Managed Exact | 从游戏模型状态投影（`managed-player-environment.mjs`，信息策略 `player_visible_v1`） | Managed 绑定动作；文本菜单光标与原生 Commit 分开回执 | 是否支持各 Read 对应内容；不支持的场景和目标类型清单 |

## 6. 一致性检查（每个 Host 适配器都要过）

1. 观察符合 schema，必需字段齐全，不含隐藏信息，可得性状态正确。
2. 已发布的目录完整：与 Host 原生目录逐项对应，执行前复验生效。另报**支持覆盖率**（有完整观察和目录的决策点占比）。
3. 回执三态语义正确，unknown 不重试；记忆推进规则（第 4 节）有正反例测试。
4. 同一 seed manifest、同一动作序列下，两个 Host 成对运行，报告第一个分叉点和原因。

## 7. 历史录制怎么用

旧 Human 录制（H Snapshot1 + 当时取到的 Reads）是**可选复用资产**，不是现成的 P1 数据，也不决定 P1 的内容。
已知缺口：`surface_card` 从未捕获；`combat_piles`、`shop_catalog` 有捕获缺口；阶段映射与终局标签需逐项判定。
做法：原件里有的事实可以投影出来；没捕获的不回填；需要推断的作为声明了假设的研究配方。新采集按 r1 的捕获合同设计。

## 8. 待定（r1 定稿前必须回答）

任务 C（2026-10-14，只接受调查范围）已给出事实。下列取舍由用户确认，主管建议写在括号里；确认前不冻结。

- "无效果"的定义：只排除游戏效果（状态、随机数、机会不变），是否允许暂停、呈现、引导与偏好元数据变化（建议允许）。
- 跨页内容：可取消且无效果的内容（普通卡牌奖励、关店后的货架、升级预览）是否自动附到父页面（建议附带）；宝箱打开、随机生成不合并。
- 可见集合排列：抽牌未揭示的顺序隐藏，只给多重集（已由原则 8 决定）；弃牌/消耗堆是否保留原生可见顺序（建议保留，省略须写明为损失）。
- 每个场景的必需内容与正常不可得状态：按 C 首批清单（地图→普通战斗→奖励→卡牌奖励→商店→营火→事件→宝箱→跨幕/终局）逐场景写入 r1。
- 详情字段闭包（描述、公开关键词、附魔、升级预览、当前目标动态值）；隐藏 DynamicVar、推荐/访问次数不加入。
- 一致包的字节/实体/时间上限：数字待测，现有 8 MiB 只是起点。
- 可得性状态：available、native_unavailable、not_applicable、unrevealed、unsupported、unknown、settling、terminal 的区分；unsupported 不能改成 optional。
