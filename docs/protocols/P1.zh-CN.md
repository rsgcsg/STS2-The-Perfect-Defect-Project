# P1 r1：完整公开信息与向前决策

状态：2026-10-16 用户重申默认充分汇总与单向选择；实施与独审进行中，尚未全局资格化/冻结。
上级：[ADR-0017](../adr/0017-p1-forward-decision-profile.md)、[架构](../ARCHITECTURE.md)。
编码与 Host 边界见 [P1 Host/wire](P1_HOST_AND_WIRE.zh-CN.md)。提交的全局候选（已发现语义、生命周期与记录验收缺口，尚未接受完成）见 [P1 全局 r1](P1_GLOBAL_R1.zh-CN.md)。本稿替代此前保留全部浏览步骤的 P1 候选方向，旧运行合同不变。

## 1. 目标与范围

让 Agent 在一个决策点看到此刻合法可取得的完整公有事实，直接作有游戏意义的选择；协议负责有明确含义的机械步骤，减少纯导航循环。尽量提供充分状态，不宣称严格 Markov 或绝无策略循环。
P1-A 是 Agent 的观察/操作/反馈合同；P1-H 是各 Host 的取数、绑定、执行与记录映射。它们落实同一版本；SDK/Runtime 端口/模型 Input/存储格式另有合同。
当前交付目标是全局 P1、Reference/Managed、环境记录转换与实际 Agent 产品链。首个取证范围曾选 exact 单人基础游戏、Defect A0；它是验证起点，不是全局完成范围或其他场景开工前置。未支持机制、角色/难度和版本逐项公布，不从目标中删除。

## 2. 信息范围与“无游戏效果”

信息当前可得，必须同时满足当前原生玩家入口资格、合法显示上下文和不改变游戏进程/选择机会的取得路径。UI/焦点/动画变化可以存在；暂停只在已核定单人稳定窗口按规定处理。
不能扣资源、抽/洗/增删牌、领取/放弃奖励、跨房间、推进游戏意义 RNG、触发不可撤回效果后才把结果当“查看”。内部对象存在或已经随机生成不单独构成公开资格；随机产生但当前合法可看的信息也不一概排除。
提取使用只读 owner 与冻结值，不实际遍历 Open/Close/Select/Generate 来凑完整包，不调用未知副作用 getter。

| 场景 | required 公有事实 | 排除/特殊资格 |
| --- | --- | --- |
| 通用 run | 当前角色/进阶、幕/层、公开 Boss/修饰、HP/最大 HP、金币、持有物、药水槽、P1 协议承诺状态 | seed/RNG/native handle/私有诊断不进模型；非当前原生公开 Boss 不提前给 |
| 当前牌组 | 多重集与各实例公开费用/升级/描述/附魔/关键词 | deck/hand/target context 分开；入口被真实禁止时按资格表达 |
| 战斗 | 手牌、公开资源/能力/充能球/伙伴、敌人公开状态/意图、完整原生可执行关系、各可查看战斗堆 | 隐藏抽牌顺序、内部未来敌人选择不提供；仅当前合法 reveal 范围保留 |
| 地图 | 当前幕可查看节点/连线/当前位置/已走路线 | 未来幕、问号真实房间和未揭示 encounter 不给；旅行是动作 |
| 显式奖励集合 | 所有已显式提供且当前玩家可查看的组、候选/详情、金币/遗物/药水等、组间关系/当前资格、已领取/拒绝状态 | 不提前生成未产生奖励；独立 CardReward、RewardsSet、LinkedRewardSet、card bundle 不能混同 |
| selector | 完整候选/详情、已选、min/max/prefs、合法确认/取消、父阶段公开上下文 | 父动作执行后才产生的候选不得提前给；隐藏用途不可猜 |
| 商店 | 当前可看库存/价格/售罄/禁用、资源/移除资格与合法详情 | 进入资格/FTUE/槽位通知/对话效果逐机制核；不自动买、卖、离开 |
| 事件/营火 | 当前文字、选项/提示/disabled、当前合法预览与后续阶段 | 隐藏分支答案、随机变换结果不提前模拟；可取消不等完全可逆 |
| 宝箱/随机发现 | 动作前给当前已公开信息；执行后给实际产生的结果 | OpenChest/Discover 的效果和 RNG 保持真实顺序 |
| 终局 | 原生已确定 win/loss、当前可得 summary 与清理状态关联 | 不等待 summary 按钮才能终局；菜单/重开属任务管理 |

每个公开对象的动态详情绑定 display context、目标/预览与当前版本。锁定/未发现遗物或百科内容遵守原生限制；不导出全部模型内部数值。
普通 Draw 可用规范化多重集，或精确原生公开展示顺序；后者明确标为展示顺序且不得复制内部真实抽取顺序。discard/exhaust 原生可见顺序保留，重复卡不合并。公共别名/摘要不能编码 hidden index/counter/排列；原生执行引用只在私有绑定侧。
P1敌人身份使用公开实体引用，不将原生数值CombatId计数器作为显示事实。兼容字段仅在与当前规范字段完全一致后归并，矛盾须拒绝，公开关键词/描述等额外事实保留。
身份替换仅作用于声明的实体引用字段，不能因为显示文字恰等于一个原生token就改写文字。不可区分的无序牌组成员使用当前观察内的匿名槽位，秘密指针与槽位的对应不跨观察保留；当前有公开可区分呈现的实体仍保留连续身份，承诺owner另存私有绑定。
程序不添加推荐、访问次数或人工“你又来了”提示。已明确作出的 P1 领取/拒绝/选择承诺是协议当前状态，必须公开，不能藏在执行器后宣称状态充分。

## 3. 全部资料怎样给

同页所有逻辑候选及允许详情一次捕获，按实体实例枚举，不按 Read kind 只取一个。多组奖励按组附 preview 和依赖关系，不能只给外层“加卡”按钮；所有新支持必须有对应原生资格与只读来源。
完整捕获后才可发布完整观察。多个 Read 同 snapshot ID 不充分；同边界封存或可靠依赖未变证明必须涵盖全部 required payload。分块只传同一冻结版本，不重读 live 状态混包。
捕获/表示/传输/模型计算分别计成本。完整 Agent 取得 required 内容后再按 InputSpec 消费；每块不是新决策/W 更新。实际 Human 浏览、环境捕获、Agent offer/consume 和模型计算分别记录。
明确最大实体/字节/保留/传输时间能力，超限拒绝，不取前 N 项伪称完整。工程数值由受审能力声明固定；规模边界和缺口进入支持矩阵，不能反定义游戏不需要这些对象。

## 4. 决策粒度与自动步骤

默认合同是充分汇总当前合法资料与单向选择，不是复制原生逐页浏览。
先通过聚合、改变选择粒度或显式协议承诺消除纯导航/查看/撤选循环；不能因实现暂缺便把这些循环永久作为P1合同。
只有精确机制证据表明在合理范围内无法这样表达时，登记具体受影响机制、信息/机会差异与可选取舍，交用户决定。
实现中的unsupported是待补缺口，不是已批准的协议例外；不得用比例猜测代替机制证据。


P1 目录由声明的映射 owner 完整发布；不是消费者随意删原生动作。原 Host 目录及复验保留原义，P1 在批准的粒度下完整。

| 意图/阶段 | P1 决策 | 可自动的部分 |
| --- | --- | --- |
| 出牌/药水，目标在当前已知 | 对原生完整 card/target 或 potion/target 关系作一个选择 | 已选意图唯一蕴含的点击/目标/确认机械步骤；有新选择则返回 Agent |
| 产生新信息的效果 | 先选择并交付父动作，再发布生成/发现等子决策 | 等待/进入已实际产生的子页；不提前选未知候选 |
| 显式独立卡奖励 | 直接选择该组具体候选或不可撤回拒绝该组 | 打开已选组、落实已选卡、已确定的返回；不替 Agent 拿卡 |
| 多组/linked/bundle | 保留领取顺序、互斥/联动关系和全部当前策略机会 | 不能 flatten 为独立卡；不可偷 skip 整个集合 |
| 多选 | 在完整候选上表达最终选择或单向累积的选择前缀；公开已选和剩余额度。原生纯撤选不必成为P1动作 | 已选意图唯一蕴含的选择/确认；若每选一步产生新资料或真实效果则重新给出完整子决策，不跨过新选择 |
| 商店 | 买哪个/移除哪个/离开等真实选择 | 在已选采购意图内进入/确认/返回；全量库存可看时不要求模型反复开关 |
| 结束当前页/房间 | 完整 P1 语义关系中已无未决选择，且声明为强制继续 | 有确切资格的 continue/close；不因原始按钮数为 1 自动 EndTurn/采购/丢弃 |

自动推进条件必须逐机制声明：本轮已授权意图蕴含该步、没有新策略分支或信息需要选择、原生当前绑定有效、预算/控制权仍有效。仅 `catalog.length == 1` 不足够。
第二类是 profile 明示的 forced-input：完整有意义 P1 关系与原生 mandatory 约束共同证明恰一项，且不存在取消/退出/等待/时机或资源分配取舍时，可由已授权 auto-policy 直接执行，不要求先调用 chooser。必须选一且仅剩一候选可作为首例，仍要核外部药水等机会；EndTurn-only 只列待逐机制资格化，不能仅凭 raw 数组判定。保存 context、auto-origin 与 Receipt，不造有效 Human N 标签。
新的可选择信息出现即发布下一决策；未知后继、写证据失败、绑定变化或预算终止按各自结果停下。有限自动步数/期限与外部 Stop 一起约束，不能隐藏无限“自动前进”循环。
有唯一必要输入的状态可不调用 chooser；是否把观察作为 context-only 提供给有记忆 Agent，由声明 InputSpec 决定，不能自动删掉训练所需的公开历史。

## 5. 奖励拒绝与向前状态

`decline_reward_group` 是显式、不可撤回的 P1 承诺，不等同原生 CardReward 的 Skip。普通 Skip 返回而不完成该组，但父 OnSelect 正常退出会断开该组的 RelicObtained 订阅；整个 RewardsSet skip 则处理所有未选奖励。三者不得混同。
只能在原生集合存在合法完成/退出路径、且该拒绝不违反强制领取义务时广告 decline。`RewardsSet.DisallowSkipping` 或必须完成的奖励需要机制专用约束；不能把所有组本地 declined 后才发现 native 无法退出，再代选一项或伪称完成。单个 CardReward 允许返回不证明整个集合允许放弃。
若某普通奖励没有合格原生单组永久跳过入口，P1 可把该组记为 declined、从本 profile 的再次选择机会中关闭；原生内容暂留，待合法退出集合时由原生处理 OnSkipped。协议状态要同时标 native disposition pending，不声称原生已执行。
本轮选定的普通独立组实现是 `open(exact group) → actual ordinary Skip → P1 closed-group`。
普通Skip的真实OnSelect退出完成当前选择界面的清理；原生OnSkipped及最终放弃仍待合法owner退出，二者分别记录。
不能只记本地拒绝然后任意领取其他奖励，因为未退出的CardReward可仍订阅RelicObtained并产生真实效果。
没有普通Skip但集合允许退出时，可保留全部聚合领取/alternative与leave_remaining，不广告未经证明的单组拒绝。
原生group_relation、reward_set_id、parent_status/parent_group_id、selection_completes_reward和选项is_native_skip
须来自本次实际owner/原生机制；null不等standalone，名称相同不等普通Skip。
所选卡以同一原生实例和同reward显示上下文的全部公开值核对；选择后未完成组的仍按当前原生事实继续提供。
每个自动子步骤消费同一次封存的完整basis并核当前owner、全部候选/alternatives和公共run/player/Read事实；
只有snapshot kind相同或找到一个select/confirm按钮不构成继续资格。事实漂移保留已交付前缀并停止自动链。

原生仍允许返回后再领取该组，因此全局P1另外提供一次性的 `reward.stop_relic_refresh(group)`：
它停止该真实 CardReward 的被动 RelicObtained 候选更新，不放弃该组；之后仍可取牌、选择实际alternative或重掷。
这是原生效果的单向表达，不是一次浏览。Host必须纯读取该 exact Reward 的已知订阅，报告
`native_relic_refresh_subscription=attached|absent|unavailable`；absent不推断曾经打开，手设候选构造本来就可能未订阅。
只有当前attached且存在合格普通Skip时广告此意图，lower为当前组open→实际Skip，完整post-source核同owner为absent后提交状态。
已absent时不再广告空操作；P1状态和观察公开该事实，同组取牌仍开放。原生重掷不会重新订阅，但会按当时规则产生新候选，必须重新捕获，不预读RNG。
`is_native_skip`只标识已核准的原生Skip选项，不声称整个父transition无效果；旧候选字段`is_pure_return`不得继续作纯度依据。
多组分别绑定真实owner；group_relation=independent仅表示领取独立，不表示各组效果可交换。恢复后新建Reward必须重新核订阅，不沿用旧ledger。
Source记录的open/Skip只有在原前缀、已交付输入和同owner后件均足够时才转换成stop_relic_refresh；不能自动改称decline。
重复打开/返回只有已证明无额外效果时才可列为机械context；未知、pause/gap、部分后件与Human/Stop均不补造承诺。
以上是本轮已选修订，尚待源码与真实机制验收；旧r1实现/历史记录不因此自动获得该能力。

领取其他奖励可能改变原生候选。P1 已拒绝的同一组不因内容变化或返回而重新开放；这是用户选定的粒度取舍。新的真实奖励组有新的 owner/occurrence 身份，不能按相同文本误并。
如果延迟 OnSkipped 会影响后续可选内容、游戏效果或 linked 奖励处置，不能套用普通组映射；必须显式给出机制专用路径或标 unsupported。不得直接调用一个 public 方法或反射绕过原生玩家入口。
协议状态至少有组身份、独立/linked/bundle 关系、available/selected/declined、native disposition pending/completed、关联操作与版本。状态随 episode/owner 生命周期隔离，断连恢复要核原件，不能从当前页面或同 seed 猜回已拒绝清单。
该状态可减少重复打开已拒绝奖励的环，但不保证所有策略选择都有效；预算停止算删失，不能算通过。

## 6. 反馈、失败与发生

一次 P1 意图可能有多个 native 子步骤。结果分：not_started、in_progress、completed、interrupted_known、unknown；同时保留每个子步骤的 attempted、原 delivered/not_delivered/unknown、cause、已知后继与原件引用。
协议本地 commitment 可成功而 native_attempted=false；父动作 delivered 可伴 child pending。completed 只表示声明意图完成，不冒称所有 native Commit/后继已证明。
部分执行后失败不能改写为“没有执行”；unknown 不重投整个宏或剩余子步骤，不回滚已发生效果。known-not-delivered 只按声明原因重观测/重选；幂等账本按确切 request/owner 绑定。
自动链必须逐步复验。新信息/机会使原计划不再唯一蕴含时终止自动链并给新决策，不能以“宏已选”跨过去。外部期限/Stop 在挂起时仍执行控制释放与证据收尾。
同封存包轮询/重传属于同一次发生；真实决策阶段/重访即使正文相同仍是新发生。P1 commitment 变化也是公开协议变化；transport chunk/隐藏 raw hash 不定义模型记忆推进。
状态充分目标不取消 Agent 的历史。Input/Model 明确实际消费、context-only、advance、reset/resume 与 gap；旧 state_digest 规则不自动兼容。

## 7. 记录、转换与两 Host 验证

上层有两条相连流程：环境→协议适配→完整Agent→操作执行，以及环境原件→验证/转换→数据使用。
Host拥有事实/执行，协议拥有公开意义与粒度，SDK拥有编码与共享映射，Runtime拥有控制/期限/Agent会话，Recorder拥有独立原件，Evidence拥有验证/转移。
共享当前公开事实捕获不依赖P1 Agent存在；P1映射在线/离线复用同一核心。后续P2替换声明的协议/适配/格式与对应能力，不复制Runtime、Recorder或Store，不把所有协议逻辑放入上层任务系统。
原生Human/程序的实际输入来源与P1标签来源分别保存；没有实际模型也可通过相同Agent程序端口运行。


环境侧记录完整 P1 捕获及其原生依据/缺口；操作侧保留 P1 意图与逐 native 步骤/commitment 变化；Agent 侧记录 offer/consume/choice。可引用同一冻结字节，不建第二套 Store。
旧 Human 原件只转换已捕获的事实。多个 native 步骤合成一个 P1 标签必须证明同一意图、完整前缀/输入和归约条件；不能把 parent+continuation 自动造为宏选择。纯导航/强制步骤不伪造 Human 学习标签。
历史转换、新 Reference 目标捕获、相同语义动作两 Host 对照和策略 suite 分开。优先新捕获补 P1 缺口，不让旧数据迁移成为主线前置。
两 Host 使用同一 P1 粒度/承诺规则；比较完整信息、目录、实体关系、阶段/效果与失败生命周期。允许 opaque 身份一一重命名及不可观察传输/动画差异；不能合并两个相同外观实体而丢关系。
首分叉后保留双方原件，不继续把后来独立选择称同前缀重放。当前公共 Snapshot 不是完整可恢复游戏状态；同 seed 不等相同 RNG/前缀。
机制矩阵覆盖、随机/学习型可靠性、策略强弱各报分母。P1 学习型 Agent 的 ref-20 至少 19/20 自然终局、0 unknown/卡死/清理不明是已选工程目标；它不替 Reference L0 全 20 条件或未遇机制资格。

## 8. 实施/接受条件

先独审本正文、Host/wire 和原生例外；实现 common capture/reducer/trace/comparator 的最小完整路径，再扩展机制。现合同公平错误与 CI 解堵独立并行。
新 profile 必须声明支持矩阵和版本；旧已合格 profile 不静默升级。每个能力依次有源码/合同、原生build、精确候选与机制运行证据，结果不能互借。

## 9. develop收敛与冻结

先独立验收基础PR187，再验收PR188及本轮修复；每个PR的合并/关闭分别取得用户批准。
组件源码采用正常merge，保持组件来源身份。合入develop只表示集成，不自动授予运行资格。
完整链路、两Host、独立原件转换、机制覆盖与所选实跑通过后，固定对外合同修订、精确包/安装身份、支持矩阵、验收套件和回滚入口，确立P1工作基线。
冻结后只做不改变对外语义的实现修复；信息范围、选择粒度、时序或失败含义改变须新修订及明确迁移。上层产品可继续演进，但不得隐式改变协议。
清理重复主入口、过时派发与已迁移实现时保留旧原件/归档读取和回滚资产；删除工作树/分支/数据仍按用户授权。
