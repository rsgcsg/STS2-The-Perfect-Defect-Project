## 2. 工作台到底是什么

**SpireAgent 工作台是同一个项目的操作入口、任务中心和可追溯对象视图。**
它串起：采集 → 原始证据/决策 → 固定数据集/分配 → 训练 → 分析 → 模型 → 本机实战 → 报告。
它不是另一套游戏规则引擎，不是只展示调试计数的 Mod 面板，不是独立云产品，也不是
把所有 Python、训练和存储塞进游戏进程。

同一事实只有一个 owning service；工作台提供角色合适的操作、依赖说明、进度和恢复入口。
界面可以有多种宿主，操作和对象身份只有一套。已训练、已导出、已下载、已安装、已加载、
当前可控制、已验证不能被一个“就绪”绿点合并。上传完成不等于研究准入，报告可读不等于
策略强，归档不等于删除、停止运行或解除 Gold 保护。

### 场景与执行位置

| 用户要做什么 | 从哪里进入 | 真正执行在哪里 | 游戏退出后的预期 |
|---|---|---|---|
| 录制人类决策 | 游戏内采集页 | 原生 Annotator；本机负责封包/上传 | 原生退出按真实边界收尾；已封存上传可继续 |
| 管理本机队列/模型 | 游戏内工作台或外部同一工作台 | 本机 SpireAgent 服务 | 服务独立存活时继续；电脑关闭则显示离线 |
| 浏览/整理项目数据 | 游戏内统一导航 | Hub 授权、业务账和存储 | 云端工作不依赖游戏 |
| 1a 有界训练/评测 | 游戏内训练表单/任务页 | 本机独立 worker，既有 ArtifactStore | 独立任务继续；重开界面可恢复观察 |
| 授权团队主机训练 | 同一训练入口的执行位置选项 | 团队协调＋受预算约束的本地或远端 worker | 游戏与本机下线不停止已提交云任务 |
| 本机模型实战 | 游戏内模型与实战页 | 本机推理子进程→Policy Runtime→Connector | 精确游戏消失即停止控制并按真实证据收尾 |

上表是目标生命周期，不宣称现有服务已具备 OS 自启动、崩溃自动恢复或全部训练 UI。
关闭面板、退出游戏、停止本机服务、电脑休眠、取消任务是五种不同操作，界面必须解释。

## 3. 游戏内可达是完整工作流要求，不是链接集合

正常用户的核心采集、数据集选择、训练提交/观察、分析和模型控制均可从游戏内完成。
所有已支持工作台任务都要有游戏内可发现入口、权限说明、运行状态和结果返回路径。
外部窗口可用于登录、系统文件选择、复杂大表或同屏研究；它必须打开同一对象/任务的
完整上下文，完成后游戏内能看到状态。不能跳去一个无关联首页，更不能让用户抄 SHA、
贴 token、找文件路径或开终端才能完成普通操作。

本机服务未启动时，游戏内显示明确的一次性准备/启动/重连路径；不得无限显示离线而让
用户自行猜命令。具体自动启动只调用已安装且固定身份的 owning launcher；不能让模型
manifest、网页内容或任意 URL 携带 shell 命令。原生安装、受保护发布、服务器恢复和
付费预算批准仍由有权限的真人处理，但任务必须能从工作台解释、打开并跟踪。

### 展示结构

| 导航 | 首屏应回答的问题 | 主要操作/下一步 |
|---|---|---|
| 总览 | 当前模型/录制/任务怎样，哪里需要我处理？ | 继续当前工作；修一个明确阻塞 |
| 采集与数据 | 正在录什么，哪些已封存/上传/核验，质量怎样？ | 录制/暂停/结束；查看队列；按来源/局/决策检查 |
| 数据集 | 哪一份固定数据能用于哪种目的？ | 筛选→预览→固定版本；查看成员/隔离/质量；送入训练 |
| 训练与分析 | 运行哪个配置、哪些数据、在哪运行，产出怎样？ | 提交有界任务；暂停/恢复；同协议比较；定位错误 |
| 模型与实战 | 模型来自哪里，本机是否可用，支持哪些场景？ | 下载/校验/准备；加载并接管；暂停；切换；报告 |
| 任务中心 | 哪些事运行中、等批准、失败或需要恢复？ | 日志/状态/最后心跳；支持的取消/恢复；打开产物 |
| 账号与设置 | 当前项目/成员/本机是谁，云和服务是否可用？ | 登录/原设备重连；权限/存储/资源/版本诊断 |

侧栏不按内部组件堆几十项。任务中心全局可达；设置与高级诊断次级展示。
数据→数据集→训练→分析→模型→实战是可点击的对象关系导航，不是强迫用户每次从头走的向导。
已有数据和模型可以从中间进入；所有结果能追溯上游，而不是重复创建同名对象。

### 游戏中常驻与展开态

常驻小条只显示：人类/AI 控制、当前模型、正在处理的动作阶段、录制状态、需要注意的任务数，
以及始终明显的“暂停并交还控制”。展开后是完整工作台。关闭/折叠不等于停止 Auto；首次操作
解释这个差别。不得让工作台覆盖或吞掉无关游戏输入；键盘焦点、Escape、弹窗优先级、拖动、
缩放和位置记忆都要验收。窗口状态是展示状态，不决定游戏事实。

模型卡主操作为“加载并接管”，前置检查和 Recorder 收尾由同一应用意图串联。内部顺序仍是
校验→加载到 Human→核对当前游戏/恢复 epoch→完成录制交接→明确启用 Auto。
“仅加载”可作次级选项；One-Step/Shadow 放高级诊断，不要求普通用户逐按钮拼接。
重复点击不得重复加载或重放投递；切页、登录回来、晚到响应不得恢复被取消的接管意图。
暂停期间可保留已加载模型；结束会话则释放控制、终止 owning child 并封存 Agent 报告。

### 表格、长任务与失败

用分页/有界增量和稳定行 ID 更新，保留筛选、选择、滚动、焦点；支持“本页”与“全部匹配”
的清楚区别。加载中、空结果、无权限、缺原件、未索引和断网必须不同，未知计数不能显示 0。
数据质量标注和本次不选不同；训练、test、Gold 的用途与曝光限制来自 owner，不由 UI 改标签。

长任务卡显示实际阶段、执行位置、任务 ID、最后观察时间、已记录用量、输入/输出引用、日志
和 supported actions。没有总量不画假百分比，没有 measured cost 不显示伪精确预计费用。
请求提交后失联显示“结果未知/正在核对”，不能直接给一个会重复提交的重试按钮。
“暂停”“取消”“恢复”只有 owning worker 真正支持时才提供；训练 checkpoint、上传暂停、
CI cancel 和游戏 Human/Stop 不使用同一条底层命令。

## 4. 应用与云的连接

```text
游戏内工作台 / 可选外部 Workbench
    → 本机 SpireAgent 应用服务（账号 BFF、任务投影、模型/采集编排）
        → Hub 已有成员/设备授权、用途/Gold/质量业务账、共享产物与任务
        → 本机 worker / 存储 / 验证与下载
        → 既有 Policy Runtime → Connector → STS2
        → 既有 Recorder 应用边界和上传工具

云端浏览器 → Hub 的同一项目对象与授权
```

不让 Hub 反向调用玩家 localhost，也不把公网账号权限变成远程游戏控制。
公网云端看不到未上传本机队列时，应显示未知/仅云端范围，不伪装成本机实时状态。
成员身份由 Hub 决定；本机设备上传凭据、个人会话和云管理员登录不合并成万能 token。
已有登录、刷新、失效、撤销、原设备重连和账号切换继续复用；不得将 R2/Modal/admin 密钥
交给 Mod。浏览器登录可能需要外部身份提供方；通过一次性、短寿命、绑定来源的回调回到
原任务，避免复制 cookie 或明文凭据。方案必须经过当前身份 owner 的审查。

计划增加的是现有服务上的有界类型化 facade 和 capability 视图，不是第二套业务数据库。
任务卡保留 owner/task ID、输入/输出 IDs、观察时间、执行位置和允许操作；它是投影，不重新
裁定完成、费用、Gold、因果或模型准入。应用意图的防重复与原生 request ID 是两层机制。
普通页面 GET 只读状态，不启动索引、训练、上传、模型加载或游戏。

本机失联但云可用、云失联但本机就绪、两者皆离线、成员被撤销、游戏重启是不同状态。
已获得许可且无需实时云授权的本机活动不应仅因云暂时断线被无关终止；涉及共享访问、
新的训练准入或新的云操作仍按 owner 当前授权执行，不缓存 Gold/权限决定来绕过检查。

### UI 宿主选择

先完成一项有界可行性验证：在支持的目标平台上比较原生薄视图＋类型化本机 API，与复用
既有 console 页面的嵌入宿主。选择依据是完整操作可达、焦点/输入、不阻塞、版本分发、
认证/Origin、防任意导航和维护成本，而不是假设 Godot 已有可用浏览器控件。
未完成验证前不引入第三方 WebView 运行时，不承诺跨平台嵌入，也不重写整套前端。
游戏控制和手动接管入口必须原生可靠；密集数据页面可分阶段复用既有视图，但外部跳转
不能成为永久缺少游戏内任务操作和状态的借口。选型不改变本节后端边界。

## 5. Policy Runtime 必须补齐的产品合同

Runtime 是模型中立的策略会话执行器，不是项目训练调度器或工作台本身。
它继续拥有完整候选、精确绑定、控制器、已知 stale 刷新和未知投递安全；
STPD scorer 只返回完整分数与选择，UI 不直发 BoundAction。

历史首次设计时的源码读取显示：Human/Stop 会先改变恢复 epoch/取消标记，但释放控制在串行操作中；
该旧风险与后续已完成的源码修复/回归须按 CURRENT 和精确回执区分，不重新宣布当前
实现仍有同一缺陷，也不把修复的源码检查当作本机性能复现。持续验收需要覆盖慢/卡死适配器、第二个 Auto tick 已持有控制器、提交前/中/后
接管、旧响应晚到、双客户端恢复、端口占用、进程退出和重新加载。

UI 必须区分“请求交还控制”和“owner 已确认释放”。目标是暂停反馈及时且不等待长推理；
Luna 提出并测量点击反馈/取消确认/控制释放的上限。建议验收基线为本机健康时 250 ms 内
可见反馈、没有在途原生 Commit 时 1 s 内确认释放；这些是待基准校准的目标，不是现状。
在途原生提交不强行撤销、不伪造未执行，安全停止后保留 Receipt/unknown。不得为了快速
按钮效果清 taint、自动重试 unknown 或在另一线程任意调用原生游戏对象。

动画中 settling、缺场景支持、暂时无控制、真正终局、明确拒绝和未知投递需要各自状态。
后继轮询是非结算观察，不生成 Human 因果证明。放宽超时不是解决所有场景转换的方案。
模型加载时间、输入长度/候选规模、首次评分/热评分、资源争用分别计量；慢模型要清楚标注，
不能删候选、静默截断或藏一个规则策略替它玩。

## 6. 全场景是什么意思，怎样证明

本次目标是当前选定、固定游戏版本/模式的完整目标流程，不是所有未来版本或未声明角色。
先由 Luna 从当前 Connector/native 合同核对完整 surface/verb/selector 清单，提出覆盖矩阵；
不能仅凭下面的用户场景名称新造 enum。任何确实尚无接口的场景都作为明确缺口交付，
不能把它从矩阵删掉以宣布 1a 完成。

至少检查：开局/继续与会话交接、地图、普通/精英/Boss 战斗、药水、奖励/卡牌选择、事件、
商店购买/移除/退出、营火、宝箱/遗物、嵌套/多选/确认取消、跨场景自动延续、胜负终局与退出。
账号、主菜单设置、安装和进程控制是应用/Host 命令，不强行变成模型 gameplay actions。
单人以外模式和其他角色是否属于本批范围必须明确展示，不能不经授权扩大到任意游戏配置。

每个矩阵格保留：公开观察与 complete catalog、模型输入、manifest support、owning action、
训练覆盖（可为零）、离线合同测试、真实加载/投递/场景切换证据、终态和剩余缺口。
统计单位分开：接口可执行、实际场景已验证、模型训练见过、策略质量，不混成“支持”。
当前默认交付为 D-Simple；在固定页面长度和记忆大小下，候选评分计算量至多随候选数
线性增长。环境覆盖独立于模型强弱；默认模型须完成完整输入/评分/执行链路和实际场景
资格。旧 B-S/B-PF/D-Simple-S/D-Simple-PF 保留原产物、测试与运行身份，不要求为了
切换默认而全部重训，也不自动把新输入或记忆资格授予旧产物。至少默认配置达到实测
日常响应目标；慢或未接入的研究变体如实标记。
后续模型接入同一能力矩阵与适配合同，不再为每个架构开一套工作台/游戏按钮。

通过分场景最短原生用例加连续跨场景旅程验证，不要求一个弱模型靠实力赢一局才能覆盖
所有场景。必要时使用合法到达的存档/人工准备；标明 setup 部分，不把人工补操作算 AI 连续
自主。缺少某个场景证据仍是缺口。拒绝、未知、取消、终局均要负路径测试；不能用一次
delivered 或一次通过验证的日志推断全流程成功。

## 7. 1a 完成门槛：一条用户旅程与一套管理能力

以下每项都需要真实操作和可核对回执，不能以页面截图、空表或 synthetic 数据替代全部。

| 门槛 | 交付验收 |
|---|---|
| A：基线可恢复 | 当前源码、包、安装、模型、游戏与服务身份一致；旧记录/队列保留；回滚可用 |
| B：游戏内入口 | 账号/本机服务可连接；核心工作台任务可发现、操作、监测并返回结果；外部视图保持上下文 |
| C：采集到数据 | 真人录制、结束/自动封存、队列、云核验/下载、来源与质量都能查看；AI 数据不混入 Human |
| D：数据到训练 | 从游戏内固定可追溯 dataset/allocation，提交真实有界本机任务，监测、checkpoint 恢复及失败可解释 |
| E：训练到模型 | 报告和共同协议比较可用；能追到数据/配置/结果；模型导出、安装/下载、加载与切换贯通 |
| F：全场景连接 | 环境场景矩阵、默认模型完整评分/投递链与连续旅程证据齐备；弱模型早死不代替未到达场景验证；接管/停止/重连/终局安全 |
| G：日常可用性 | 无需终端串流程；切页/重开不丢任务；离线/权限/失败清楚；界面与游戏不被训练/推理阻塞 |
| H：交付管理 | 审查、选定 CI、原生/服务验收、精确发布与真人签收各自完成；已知限制可见 |

产品黄金旅程：同一个成员从游戏内采集一段真实数据→确认上传/核验→管理并固定训练数据→
提交小型真实训练→查看 dev/基线/错误分析→保存并本机准备模型→在真实游戏运行→暂停/切换/
结束→查看独立 Agent 报告。可使用已有合格来源补足 run 隔离，不强迫一段新录制单独成为
有效训练/评测集。另一条复用旅程从已有数据/模型进入，不重复安装和重新登记电脑。

补充恢复旅程：关面板、游戏退出、工作台重开、云失联、登录失效、模型慢/失败、明确 stale、
unknown、训练中断、缺原件和下载失败。成功按钮不能掩盖这些状态。

B/C 定义不在本轮改义：B 共享一份观察与全部候选，从最后层各动作读出位置评分；默认
mask 隔离候选且分支 position 重置。冻结 Qwen 的固定文本一次＋集中 query 一次是同图
等价执行，不是逐候选重读。C1 的预测含义须后继监督，C2 是每动作多个读出；C 仍不属于
1a 四配置实现范围。权重/文件身份严格核对，浮点评分按预先声明容差和候选绑定核对，
记录近并列排序变化，不能因微小浮点差无理由重训或追求逐位相等。

## 8. 独立的环境交付与管理

环境是独立产品能力；模型、人类文字客户端和评估工具都可以使用。同一环境不导入
STPD，也不依赖某个模型是否获胜。环境管理与模型研究分别验收，工作台统一呈现。
详细边界和当前缺口见[环境与场景管理](plans/ENVIRONMENT_AND_SCENARIOS.zh-CN.md)。

- 游戏接口：当前原生逻辑页、完整可执行菜单、执行复核与真实结果；不混入未访问页、
  隐藏 RNG、存档内部或未来分支。
- 环境管理：发现/准备/启动/停止、版本能力、隔离实例、种子、合法存档、场景保存/恢复
  与复制分支；这些是 Host/应用操作，不是模型 A(S)。
- 场景库与评估：固定起点和能力范围，复用同一管理服务运行；可分别判定接口正确性、
  跨 Host 一致性、吞吐和策略质量。人工/特权 setup 明确记录，不冒充模型自主到达。
- 真实游戏是原生参照；Managed Host 是独立适配和资格。种子重开、房间起点恢复、
  任意决策点快照是三种不同能力，不能统一标成“支持恢复”。

## 9. 1a 研究闭环与 1b 分界

1a 上述门槛通过并由用户接受后，才把主要执行资源转向 1b；源码合并或四格十步试跑
不能单独打开阶段门。可以提前做不消费预算的 1b 容量/成本方案，但不以“以后 1b 再补”
搁置游戏内操作、全场景和本机使用缺口。

当前用户范围将约一万条合格决策/交互的真实训练尝试和 M/Z/O 有界比较放进 **1a**。
不是一万局，不保证库存已足够，不通过重复计数、混合标签/完整后继或放宽 Gold 来补量。
记录来源、独立 run、重复关联、场景/长度/候选分布和 train/dev/test 用途；真实不足是
未完成条件，不用合成复制伪装目标规模。无需所有变体各训一万条。

默认模型路线是 D-Simple＋轻量独立动作编码。页面、旧内部记忆、上一实际交互和可用的
原生公开反馈共同更新表示；没有原生反馈时不编造。K1/K8 指持续内部向量数量，不是
人工历史文字或固定语义槽。完整菜单的各候选只读这一步的表示，不逐候选改写正式记忆。

最小比较按依赖开展，不展开全笛卡尔积：

1. 当前页面基线与默认模型训练→导出→独立评分→运行闭环。
2. M2-K1 与同结构独立训练 Reset-K1；K8 与 Reset-K8 比较容量/读取瓶颈。输入和结构
   相同的 M0/Reset 不重复算两种实验；严格只看 S 的基线与带上一实际动作的 Reset 分清。
3. 出现遗忘/覆盖或表示坍塌迹象再比较 Gate/R；多个槽不保证不坍塌，不能强制每槽有
   人工含义或以互相正交当作有效记忆。保留负面结果。
4. 固定主体比较 scratch、冻结 Qwen、Qwen LoRA；冻结权重的记忆路径仍可能需要穿过
   backbone 的输入梯度，不能照搬旧 PF 固定特征缓存成本。
5. 固定图/记忆/数据比较 N、N+Z、N+O、N+Z+O；Z 只用实际执行且有合格后继的分支，
   O 未来标签仅作训练目标。输入标签不能伪造后继或结果。旧 O-chain 的 Qwen teacher
   不暗入 scratch，新简化目标独立命名。

小 B 保留工程参考，小 D2 是后续有界实验，不阻塞默认产品链路。先验证接口、历史
利用和成本，再解释质量；不会因一次小实验不佳永久淘汰一个结构。

1b 以真实提高模型质量为中心：更好数据、规模、结构、强化学习或搜索由固定评估中的
失败原因决定。1a 可以训练较大模型，但不以达到“最强”作为工程阶段退出条件。
付费执行仍需明确预算；普通安装授权不等于云消费或发布授权。训练使用可追溯配置、
数据/产物、checkpoint 和可核对的终态；不要自动展开无上限训练。
