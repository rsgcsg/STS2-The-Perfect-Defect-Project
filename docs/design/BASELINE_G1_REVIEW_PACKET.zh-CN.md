## 1. 大白话导读：这次到底决定什么

我们要做的不是一个“把游戏文字塞给模型、让它选编号”的脚本，而是一套能长期演进的系统：游戏提供公平信息和可靠动作；记录能说明当时发生了什么；研究把合格材料变成Agent；产品负责让这些事情在正确机器上、用正确数据和预算完成。

第一款Agent准备采用**固定时机程序＋带持续记忆的轻量M2**。程序告诉模型什么时候可以认真选；模型记住真正看过的历史，在完整当前合法集合里选择。先学选择N，后续有合格后继再学Z，有终局/战斗结果再学O；RL则需要自己的奖励、时间和行为轨迹，不能把前面文件改个名字就开始。

A仍允许生成式、检索式、多个模块或完全规则Agent。它们不必都训练，也不必都用Human数据。14类完整旅程已用于检查接口是否被M2绑死；视觉、可分支模拟、多人等真的不兼容语义须另有能力/profile。一个主系统不等于所有使用方式都伪装成同一种条件。

G1批准的是“设计已足够清楚，值得依此实施”。G2证明第一次小而真实的闭环；V1把范围和产品旅程做全、把reference Agent接顺；G3冻结一个可复用稳定组合。之后R1正式交付，R2持续研究。**能完整运行、能流畅处理流程、游戏策略强，是三种不同成绩。**

## 2. 三条链怎样联合成一个系统

```text
真实世界/Host ──公开Frame/事件/完整C──→ 封装Agent
       ↑                                   │
       └────唯一受控Act / Await / Abstain────┘
       │事实与来源                │实际输入/状态/请求/结果
       └────────原始记录与Evidence─────────┘
                         ↓
      用途/分组 → 协议轨迹 → 组件输入 → N/Z/O/RL目标
                         ↓
            训练或无训练构造 → Agent包 → 独立评价
                         ↑
       应用服务：作业、资源、产物、权限、恢复和分发
                         ↑
                 库 / CLI / API / 游戏内Workbench
```

第一链保证“是什么、能看什么、能做什么”；第二链保证“用什么学、产物如何使用、是否有效”；第三链保证“谁在哪做、花多少、哪里恢复、用户怎么操作”。共享身份和产物关系，不共享规则/研究/授权权威。

以M2为例，人类照常玩游戏，Annotator抓公开曝光和真实输入/执行关系。验证后按新A规则投影，再按AG01的实际消费规则整理顺序数据。未来结果只进target。真实训练产物与renderer、词表、记忆规则、时机程序一起封成Agent，回到指定Host运行，再报告策略与工程表现。现有Human text五verb与旧M2接缝不够完整，新A必须补齐目标capture和训练/运行一致性；现有DSimple无标签事件推进等机制则应复用。

其他路径也完整：预训练生成模型可直接封装评估，不经过Human训练；在线RL可以从自己的轨迹学习；规则Agent可以零训练；离线分析器无需开游戏。执行系统不能把所有任务都硬塞进“录Human→训M2”按钮。

## 3. 供你批准的具体设计决定

包括D01在内，以下均是待讨论的**推荐决定**，并非已获得用户接受。推荐并不表示已实测最好。

| 决定 | 推荐内容 | 为什么、代价与替代 |
| --- | --- | --- |
| D01 主系统 | A事件合同是候选；Host/协议核心/Agent职责、事件或边界视图均待确定 | 保留原生异步机会和不同Agent；固定边界可在Agent内做，外部B-view另profile |
| D02 首发资格 | 基础单人全角色A0–A10为设计目标，Defect A0先验；固定构建/modset、首局内选择至summary退出 | 范围可实际完成且包含全部范围内Hook；各角色/升阶分批资格；多人另行设计 |
| D03 信息/表达 | 当前已进入逻辑页完整公开内容＋已揭示提示/预览＋历史，typed为主、对象展开renderer | 避免未打开页聚合与隐含曝光；大型目录通过缓存/分页减成本 |
| D04 动作 | 完整当前public input relation；List/Prefix/Resolve只读，Act原依据复验 | 生成/检索无需全评分；不能用execution Hand目录代当前可点击集合 |
| D05 事件与恢复 | 发布cursor、capture尝试/失败、曝光/消费和落盘分别记；有限buffer，诚实gap；不承诺跨原生进程透明恢复 | 比“一个序号证明完整”更复杂，但可定位丢失与重传；显式新segment优于伪恢复 |
| D06 输入/结果 | admission、delivery、public outcome、forensic proof分开；unknown delivery核原请求，不自动重发 | 支持已知在途输入，避免结果慢就误报投递未知；旧Runtime需要适配 |
| D07 Human/data | 公共曝光与输入/执行双轨；T/R/H/D与各目标资格独立；旧原件保留 | 不能保证旧语料全部可用，可能某目标为0；不通过伪造顺序凑数量 |
| D08 首个Agent | AG01 LightActionM2内核、scratch、K1、sequence-N，固定TimingPolicy | 优先可解释小闭环；旧width48路径/旧Public M2不等同新recipe；K8/Reset等保留比较 |
| D09 训练/评价 | 新A consume接缝复用现有序列机制；bounded episode TBPTT；dev选checkpoint、sealed-test隔离 | 近似carry明确报告；不要求所有14类先训练；具体run参数开跑前封存 |
| D10 后续学习 | G2后可在合格子范围pilot；Z/O按目标资格、RL按行为/奖励/时间合同进入 | 不等待所有产品完善才发现模型问题，也不把小范围结果泛化全游戏 |
| D11 作业/资源 | 可信固定workload、显式target、有限slot、预算/use预检、journal恢复 | 不先建设万能调度器；现有provider逐项适配到共享应用合同 |
| D12 权限/离线 | 私有本地活动独立；共享新用途/提交/resume在线复核；已有授权窗口内可继续，撤销有真实停止与派生处置 | 不承诺擦除已下载字节；离线包许可必须明确，不能靠缓存绕权限 |
| D13 产品/旧目标 | A–H保留；默认新Agent全范围＋旧模型兼容矩阵替代四模型强制全验；约10k及M/Z/O等1a研究义务保留 | 是实质协调，需你批准；工程基线、正式产品和1a研究完成分开报告 |
| D14 门槛/性能 | G1接受方法与范围；G2小链；V1完整覆盖/连续任务及测量；G3闭包；科学优势在实验中判断 | 30attempt等是拟议有限工程验证，不能称99%可靠；性能配置pilot后预先封存 |
| D15 交付/变更 | 同一服务连接CLI/API/GUI；完整产品需游戏内旅程；发行配对版本/rollback；扩展按影响重验 | 不把CLI小闭环叫产品完成，不每次模型更新都重装全部系统 |
| D16 批准与授权 | 你读懂并明确接受版本才通过G1；实现/训练/game/费用/安装等按后续有界包授权 | 批准设计不自动启动运行；已授权包内无需逐命令确认 |

数字配置如buffer起点是待测工程初值，不是游戏规则或性能承诺；调整不许改变“不静默丢事件/不裁C”等语义。科学超参数/预算、真实样本量和具体硬件在执行manifest固定，不需要本轮凭空选择。

## 7. 审计结论怎样阅读

审计分三步：历史/现有事实核对、各领域独立反例审查、候选完成后的独立整体审查。所有发现都要有修订或明确后续归属；source/test不冒充当前安装、录制、训练或科学结果。

本轮关键修订包括：独立capture failure账、防止“连续序号=完整捕获”；delivery/outcome分离；利用已有DSimple序列机制；把阶段指标推到正确gate；协调四模型旧要求与默认Agent；保留1a真实训练/比较义务；G2后有限研究pilot与V1工程并行。详情、精确依据、执行检查和review状态以审计文档为准。

“设计材料可提交批准”只表示目前没有已知未处理的阻断设计问题；不保证未来实施不发现问题。已知的buffer初值、性能pilot、实际新数据量、神经推理成本、全场景Human/运行、云/发行都是明确后续测量，并非假PASS。
