## 本次协议细化的明确修正

- 用户指出 C-H 与 C-S-query 没有独立契约差异：采纳，C-H 改归自动附带资料配置，撤回独立协议分类和据旧合成数值给出的优先推荐。
- 用户区分 Agent 一次查看/分步查看与 Host 原生/直接读取：采纳，两侧契约及中间映射分别命名；相同上层需要用内容、时机、效果、异常和成本验证不同实现。
- 原生打开/读取/返回不必三次昂贵模型推理：采纳，固定 Agent 程序、状态消费、协议请求、native 操作、模型调用分计。旧 probe 调用数保留为历史假设，不用于淘汰原生路径。
- 遗物、药水、卡牌详解、关键词和预览进入正式对象/曝光/来源表；公开动态说明不等于 seen/unlocked 控制下的 inspect 页面文案。
- 新[详细方案](BASELINE_PROTOCOL_OPTIONS.zh-CN.md)提供三种 AP 与四个完整组合、共同 OP-S、具体资料配置及异常恢复；没有决定默认或开始生产实现。

## 2026-10-07：L-N 首版与表示/模型接口

用户倾向L-N，允许有具体工程依据的小范围妥协，要求把卡牌详情/升级、目标预览、全部适用操作、loop/缺失/效率责任及生成/非全量评分模型写清。新[L-N v1规格](BASELINE_LN_V1_SPEC.zh-CN.md)给出64行操作承诺和明确暂缓；单人Defect标准A0是本轮首验范围建议，未当作用户已批准。

表示是Agent协议的一部分：公开对象/原生文字/展示关系可直接结构化；typed模型输入不等于JSON文本token。Agent是直接对接协议的封装体，模型是内部任务组件。合法集合完整不推出每个模型必须全评分；现Runtime确有scores长度约束，新Choice/prefix/Resolve需有版本的端口设计。Agent内部shortlist不能改环境权威目录。

原生target focus改变渲染卡牌说明及升级inspect控件已有源码依据；缺星费/焦点投影、holder完整可达、open-Peek/potion-hover、部分mouse续接及终局路由均作为实施缺口，不用这些缺口默认淘汰L-N。game outcome与包含summary导航的Agent task complete分开，防止过早结束承诺旅程。

用户随后明确“记录”重点是Annotator能否支撑学人类，而非API日志。新[Human学习闭环](BASELINE_LN_LEARNING_INTEGRATION.zh-CN.md)据当前源码确认text Human机制只有五类verb，不能把更广canonical主链当完整L-N展示/选择历史；输入前观察、Human选择、连续prefix与后继/结果逐层资格化。已存在的不同M2路径分别保留原义，生成式动作JSON可派生，Human工具调用/思维不可虚构。

用户指出快速连出、入队后复验/取消是历史核心问题。新[排队时序专题](BASELINE_LN_QUEUED_TIMING.zh-CN.md)核对原生FIFO队列、持牌UI先释放、执行时重验和条件回手；当前Annotator已有H与execution S分离及精确边界保护，不能继续沿用旧overlap数字。离散事件可以表达异步原生过程；强制全结算是额外profile/策略限制，不默认无损转换Human示范。Runtime的stableSuccessor当前并不证明全结算或canonical后继。

用户最新纠正：H的动态捕获不等于稳定GUI，协议不必复制原生时序；带说明的合理假设、执行状态重表达和稳定边界是正当设计。重新回读上层原始讨论后，[综合方案](BASELINE_PROTOCOL_V1_SYNTHESIS.zh-CN.md)区分R实现/Π部分投影/α观察，T轨迹/R重放/H保真/D重表达四类声明；从动作覆盖不能推出全部轨迹满射或随机过程等价。LN-B1与LN-E1共享底座，模型自主动作/等待是明确能力目标。之前“原生异步应为默认”仅作为历史建议保留，不强制用户接受。

用户再次明确：自主时序是整个Agent的能力，不要求单个模型具备全部功能；B1可能只是E1上的稳定实现。新[完整蓝图](BASELINE_AGENT_PROTOCOL_BLUEPRINT.zh-CN.md)区分B-style Agent on E与外部B-view，推荐前者作为首个P1参考消费者；LN-B1保留为外部边界合同，不把内部调度误命名为第二协议。四种Agent原型分别说明固定/学习组件和整体评价，ProtocolTrace与AgentInputTrace分层。

用户选择A作为主系统方向，并要求M2/N/Z/O/RL/生成式等各自完整采集、整理、训练或无训练构造、运行及评价。随后明确这些案例用于检验/调整整个系统，不能强行迁就协议。[A三链联合评估](BASELINE_A_SYSTEM_JOURNEYS.zh-CN.md)补充14类消费者、三条产品执行旅程、Host连接及15个工程压力案例。方案A选择已确认；其余GD决定及完整G1保持待接受。原型P1–P4增加AG01–AG04别名，正式19任务ID不改。

用户要求完整准备并独立审计G1，查历史/实现/外部依据，包含全套设计及大白话导读，并明确自己阅读理解批准才通过。新[G1候选](BASELINE_G1_REVIEW_PACKET.zh-CN.md)把GD待决表收敛为D01–16推荐决定与C01–15合同；G2小闭环、V1自主主要流程/产品、G3工程闭包与科学提升分开。G2后允许获授权的合格子范围pilot，既有1a约10k及对照研究义务不静默取消；四模型旧要求与默认模型冲突列为需用户批准的替代。

2026-10-08用户澄清：此前“A已选”表述过强，D01与协议细节/职责边界仍待确定；不是固定Agent只对单一玩法口或永久禁止所有任务管理。新[RC2](BASELINE_G1_AGENT_BOUNDARY_AND_BUDGET.zh-CN.md)比较Host侧/协议核心/Agent侧与BND职责分配。全角色A0–A10为目标、Defect A0先验；教程默认管理准备关闭；允许有假设、有损的任务数据转换，声明用途与非保真；Agent对外交付、Model具体计算。补合成上下文/候选预算及现行规范地图，旧模块按理由复用或改造，不批量为改而改。

用户随后暂定BND-2，要求解释协议数据全面性、完整Agent交互和文本/直接结构输入的两个M2全场景设计。[双模型详解](BASELINE_BND2_TWO_M2_MODELS.zh-CN.md)将暂定职责方向与仍待定D01细节分开，Model-T复用LightAction内核，Model-S是新的对象/属性/关系编码与结构动作图；两者在相同Agent组合中对外交付，不将结构化JSON直接等同模型输入或全场景能力。

## 怎样维护这份沿革

1. 新决定写入当前 owning 规范，沿革只记录来源、修正与替代关系，不复制全部当前状态。
2. 标为假设/候选的内容须经证据和审查才可接受；旧助手总结不是自动权威。
3. 对话没有覆盖的细节可以由工程调查提出方案，但不能冒称用户已经指定。
4. 原产品/团队/环境/模型总纲的现行义务如需修改，通过明确决定协调；不能仅因这张表更晚就删除旧目标。

本表是相关要点的可公开交接摘要，不是所有私有历史的全文或对所有旧结论的重新验证。新发现的冲突在对应任务中追加证据和决定，不隐去旧含义。
