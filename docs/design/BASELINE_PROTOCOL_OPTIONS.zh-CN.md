# 三套交互契约与四个可落地组合：Agent、Host 和映射的完整设计

日期：2026-10-06。版本：0.1。性质：**P3/P5 详细设计候选，尚未接受、实现或完成运行资格验证。** 首发比较范围暂定单人、当前已核对的 STS2 v0.111.0 机制；这是为了给出可执行的候选范围，须由 G1 接受。多人、特殊 Hook、其他游戏版本另列能力，不冒充已覆盖。

本文回应两个要求：给出几套能从开局一直解释到终局、记录和学习的方案；每套明确 Agent 看见的契约、Host 提供的能力，以及适配器怎样连接它们。符号和消息名都是**建议语义**，不是已经存在的 API/schema。既有 ADR-0015、text-menu、Read 和旧模型仍保留原义；新增查询/资料包 profile 若偏离已接受的原生逻辑页信息规则，必须经明确设计决议和版本化实施，不能借本文件悄悄修改旧合同。

阅读路径：先看第 1 节四个组合，再读第 3–8 节的具体规则；第 9 节用完整轨迹比较；第 10–13 节说明学习、成本、实现和验收。相关原生行为见[场景册](BASELINE_SCENARIO_SPEC.zh-CN.md)，基础需求见[P0/P2](BASELINE_FOUNDATION.zh-CN.md)，模型和任务合同见[P4](BASELINE_DATA_AGENT_CONTRACTS.zh-CN.md)。

## 1. 我们实际在比较什么

```text
封装 Agent（信息获取策略、编码、模型状态、推理、选择）
    ↕ Agent 契约 AP ＋信息配置 IP ＋动作配置 OP
环境适配器（映射 MP、请求进度、曝光记录；不做策略选择）
    ↕ Host 能力合同 HC
Host／Connector／原生 STS2
```

AP 是 Agent 可以表达什么操作、怎样接收信息。HC 是 Host 能做什么、前提和效果是什么。MP 规定一个 AP 请求如何调用 HC，何时完成、失败停在哪里。IP 规定资料内容和提供时机，OP 规定保留哪些原生选择阶段。它们是职责，不要求拆成五个进程。

完整配置身份必须包含 AP/IP/OP/HC/MP 的版本和内容摘要；Host 实例、游戏/组件/构建另有身份。任一语义变更都形成不同完整配置。HC 或 MP 改变时，只有经一致性验证，才可保持 AP 兼容。相同 JSON 形状、同样拿到几张牌不构成行为等价。

### 三种 Agent 侧契约

| 契约 | Agent 怎样取得额外资料 | Agent 必须维护的交互位置 | 真正不同之处 |
| --- | --- | --- | --- |
| **AP-L：原生分步浏览** | 选择当前原生可用的查看/展开；收到页面或 tooltip；再选择返回/关闭 | 当前真实 owner、浏览/目标/暂选阶段 | 查看过程暴露为多个协议操作；中途可改变打算 |
| **AP-Q：一次资料请求** | 选择 `Inspect(当前目录中的 ref)`；一次请求返回资料和实际完成状态 | 游戏选择阶段保留；纯资料请求没有额外的 Agent 页面栈 | 原生机械查看可由适配器完成；Agent 决定要什么资料，不逐步决定已约定的机械返回 |
| **AP-B：固定资料包** | 每个可决策观察自动带配置指定的全部当前可得资料；没有额外 Inspect | 游戏选择阶段保留；资料包有完整性和版本 | 信息取得不再是策略动作；每个观察的资料边界预先固定 |

AP-L 也可以在 Agent 内用固定程序执行“打开→读取→返回”，而不为每个操作调用神经网络；该程序属于 AgentSpec。AP-Q 可以由原生 UI 实现，不能把它定义成“必定直接读取”。AP-B 也不是无限全知，而是限定、可验证的公开资料集。

### 四个具体组合

| 组合 | Agent 侧 | Host 侧和映射 | 信息/动作配置 | 适合解决的真实问题 |
| --- | --- | --- | --- | --- |
| **方案一 L-N：原生浏览** | AP-L | HC-N 原生逻辑页/提示/执行；MP-L 一步对应一个已绑定的原生语义操作 | IP-L 按实际展示，OP-S 保留选择阶段 | 需要原生时机、浏览策略、Human 轨迹对应；优先复用原生路径 |
| **方案二 Q-N：一次查看，内部走原生** | AP-Q | HC-N；MP-QN 有界地打开、读取、返回，报告中途状态 | IP-Q 基础＋按需资料，OP-S | 想让 Agent 使用简单请求，又暂不新增大量直接公开事实抽取 |
| **方案三 Q-D：一次查看，直接公开读取** | AP-Q | HC-D 已资格化纯 Read；MP-QD 验有效来源和绑定后返回 | 与 Q-N 相同 IP-Q、OP-S | 减少 UI 切换和恢复负担；研究查询策略而不绑定界面实现 |
| **方案四 B-D：资料包自动提供** | AP-B | HC-D 加同时点多 view 捕获；MP-BD 组装完整资料包再发布 | IP-B 下文固定资料闭包，OP-S | 先研究出牌/选择与时序学习，减少“模型没主动查资料”这个变量 |

这是三种 Agent 契约、四个完整组合，不是四套全部重写的产品。四者共用原生事实抽取、合法目录、执行、记录和大部分错误处理。Q-N/Q-D 使用相同的宽 AP-Q 语义：请求可能需要时间、可能存在已声明 UI 效果；具体能力标志和成本仍不同。如果任务要求“任何查看都不得改变 UI”，它增加了 `pure_only` 能力要求，Q-N 不能满足，不能宣称可替换。

**旧 C-H 归入 IP-Q 的一种自动附带配置，不是第四种 Agent 契约。** 旧 C-L/C-S-query/C-S-bundle 分别与 L/Q/B 有关联，但不是新规范的别名或自动兼容承诺。本文不给任何方案默认胜出地位。

## 2. 为什么保留这几套，而不凭喜好选一个

| 真实依据 | 导出的设计需求 | 不能由此推出的结论 |
| --- | --- | --- |
| 原生浏览改变活动页、overlay 和可能的战斗暂停；建牌网格、订阅变化、动画也有成本 | L-N/Q-N 需要明确 owner、恢复和操作中断；Q-D 有减少 UI 变更的工程动机 | 没有测延迟，不能说原生必定慢、一定多三次推理 |
| 现有 Read 已做 Snapshot 绑定和目录校验 | Q-D 可复用有限公开读取；值得调查原子批量捕获 | 一次 Read 存在不等于多份 view 已在同一时点取得 |
| 对象事实投影已有动态遗物说明、公开计数、卡牌预览；text-menu 又按展示状态裁剪 | 取得事实和何时交给 Agent 必须分离；详情不应只靠模型记住名字 | 可提取不等于此时可公开；内部字段不自动公平 |
| 选择器、奖励、移除、营火、宝箱具有不同的原生完成/取消机制 | 四案保留真实阶段，不用一个万能 `select`/`cancel` 猜规则 | 模型或适配器可自行重建合法性 |
| 用户要封装 D-M2＋时序 N，旧 Public M2 又拒绝 Read | 必须设计新的事件消费/查询适配和数据资格；B-D 是排除查询策略变量的一种候选 | B-D 必定最好、旧权重/旧轨迹已经适用 |
| 老 Human 记录不一定有新资料包所需同时点事实 | L-N 可作原生参照，Q/B 转换需单独报告缺失 | L-N 自动获得全部历史资格，或 Q/B 必须丢弃所有旧数据 |

前三项源码入口在第 12 节，原生行为的确切 DLL 身份在[P5 证据](../evidence/BASELINE_P5_EVIDENCE_2026-10-06.md)。这些支持设计取舍，尚不支持胜率、吞吐或全场景资格结论。

## 3. 四案共用的硬规则：先把“一个决策”说清楚

### 3.1 握手与观察

任务启动时核对游戏/Host/Connector、AP/IP/OP/MP、模式与角色支持、必需事实族、历史/恢复和表示上限。必需能力缺失则拒绝该配置。新环境 generation、actor 接管、profile 变更都必须显式记录；不在一局中偷偷切换方案来解决错误。

每份观察包含以下概念字段；名称不是旧 wire 的保证：

| 字段 | 具体含义 |
| --- | --- |
| `environment_generation / observation_id / occurrence_id` | 本次环境代次、不可变观察身份、真实发生位置；重传同一发生不另造 occurrence |
| `context_revision / owner_ref / phase` | 当前绑定域、原生输入 owner、目标/暂选/预览等阶段；不同域变化不能只比较一个未覆盖它的计数器 |
| `public_facts / availability` | 当前实际提供的事实；其他资料可取得、此时禁用、未揭示、未知、未支持分别表达 |
| `actions / catalog_digest / catalog_complete` | 当前 OP-S 全部可提交原生语义动作和绑定；disabled 项可解释，但不混入可提交集 |
| `inspection_catalog` | L 的已绑定展示操作，Q 的有限 Inspect refs；B 无额外查询菜单 |
| `event_cursor / gap / continuity` | 已提供的公共历史位置、缺口与连续性；不能据相同画面推断无缺口 |
| `view_sources / completeness` | 每份资料的来源、上下文、捕获位置、完整性和失效条件 |

处于动画/自动续执行而没有可操作 owner 时发 `settling`，不伪造“默认继续”。轮询、网络心跳、无新事实的 observe 不成为新的模型时间步。完整目录可以无损分块运输；收到 manifest/count/digest 对应的全部块之前不能标 complete 或开始选动作。资源不足时显式拒绝/暂停该 Agent 实例，不能截 top-k。

### 3.2 OP-S：本轮四案统一保留的动作粒度

为避免同时改变信息和动作两个变量，四案使用同一候选 OP-S：保留原生真正的目标、暂选、预览、确认和取消阶段，省略滚动/像素坐标等设备步骤。卡牌、目标、药水槽、商店项目都由当前目录发不透明句柄，执行时原生复验；消费者不构造 native operand。

例如有真实目标阶段时是 `ChooseCard → Target/Cancel → native effect`，不是适配器替挑目标。无独立中间阶段的原生完整意图无需凭空拆开。把已知 card/target 合为一个请求可作为之后的 OP 变体，必须有逐机制的“无新增信息、效果、选择机会”证明和新身份，不能在这次成本对比中一边合并、一边拆开。

选择器用原生实际候选、有效约束、已选状态和控件。手牌满额替换与网格禁止加选不同；空集合可能自动完成，不一定产生 Agent 决策；min=0 也不能机械等同 Cancel。看到候选并不授权任意子集组合，只有当前原生支持的 toggle/replace/confirm 等进入目录。

### 3.3 请求、反馈与副作用

Agent 一次提交一个目录内请求，带 observation/context/catalog 绑定和 request ID。相同 ID 相同内容只查原记录；同 ID 不同内容拒绝。提交前旧绑定失效则不投递；投递后 unknown 只核对原尝试，不能换 ID 重试。当前实现是否已经满足每条能力须单独核对，本段是新设计要求。

反馈至少分开：请求是否接收、是否投递、实际公开后续状态、是否还等待子选择/续执行、观察绑定是否仍有效。法证通道另存 Commit/parent-await/因果证明，不把私有证明自动送给模型。`delivered` 不等于 `committed`，也不等于 `settled_successor_proved`。合法之后观察只是之后观察，除非 owning 因果证据支持更强结论。

对副作用分别列 UI 变化、暂停状态、控制占用、资源/随机/选择机会变化、经过时间。不是一个 `read=true` 就把它们抹掉。管理 Stop/释放控制永远不靠模型选择；停止请求、原生取消和已确认停止也不是同一状态。

## 4. 公开对象与详情：小东西也要有完整规则

### 4.1 一个详情对象由什么组成

`object_ref` 表示当前真实实例或明确的预览对象；`definition_ref` 表示确切内容版本的定义；`display_context` 表示手牌、牌组、商店、升级预览等；`captured_at` 标实际提供位置。三种内容分开存：稳定定义、实例公开状态、当前上下文显示。**动态说明不能按卡名/遗物名缓存。**

| 对象族 | 必须保留的公开内容 | 详情关系与边界 |
| --- | --- | --- |
| 卡牌 | 实例、所在公开区域、升级状态、原生当前费用/X/星费及可见变化、当前描述、附魔/修饰、选择状态 | 当前 tooltip 关键词和原生提供的卡牌预览；预览不是手牌/动作；升级预览不是已升级；未知 context 不回退成“准确基础说明” |
| 遗物 | 持有实例/公开次序、名称、当前动态描述；计数只在原生 `ShowCounter` 时给 `DisplayAmount` | tooltip 关键词、关联生成牌预览；不可公开内部隐藏计数、未解锁图鉴或未揭示未来遗物 |
| 药水 | 具体槽/实例、当前名称/说明/可用状态、公开目标提示 | 关键词和预览；使用、丢弃、关闭分别是原生操作，不能用查询触发；目标合法性看目录 |
| 角色/敌人 | HP/block/公开资源、公开状态与层数、当前公开意图及展示值 | 意图/状态说明仅原生可见部分；不得给敌人内部未来计划或私有 AI 参数 |
| 状态效果 | 所属对象、原生显示层数/持续/标记、当前说明 | 未显示的倒计时/触发内部量不公开；数值和描述可能随上下文变 |
| 球/召唤物/特殊资源 | 原生公开类型、排列语义、显示值、当前提示 | 被动/激发等原生说明；不由适配器算一次未来结算来生成“详情” |
| 牌组/战斗牌堆 | 完整可看成员、多重性、公开实例状态、pile 身份、公开排序规则 | 抽牌堆不泄露底层真实顺序；公开置顶信息走来源事件，不把普通列表排序当置顶证据 |
| 商店项目/服务 | 当前项目、价格、金币、库存、原生可购买/不可购买状态、服务阶段 | 卡/遗物/药水引用其当前展示详情；不预读购后补货、折扣 Hook 后结果 |
| 事件/营火/地图/奖励 | 当前已展示文本、图标含义、锁定原因和选项；地图当前可见结构与可走节点分开 | 不能展开下一层随机结果；奖励组关系和来源必须保留 |
| 关键词/关联说明 | 原生显示名称、说明、语义图标、合法关联 refs | 类型未识别就声明缺失；有循环使用已访问对象引用，不无限展开也不静默丢边 |

球、特殊资源、图标语义和未知 tooltip 子类的这一目标**尚未被现有两个 tooltip 类型的实现证明完整支持**。能力登记逐类完成，不得因为上表写了就宣称产品已支持。

关联闭包仅遍历此时公开提示实际提供的关系，不遍历整个游戏图鉴。例如遗物提示展示一张生成牌，可以给该预览；不能据内部类关系继续枚举所有未来随机生成物。正文、颜色、正负变化、图标如果承载含义，转成明确语义字段；纯装饰可省，不能盲目 strip 后声称无损。

详情还必须区分 **HUD/hover 动态说明**与**原生 inspect 页面文案**。现有遗物 inspect 读取原生实际渲染的 title/rarity/description/flavor，并受 seen/unlocked 规则约束；不能拿 RelicModel 的动态说明替代该页面并宣称同一内容。卡牌 inspect 的当前显示、升级预览开关及翻页也是独立上下文。Inspect ref 因此携带 detail_kind 和 display_context，例如 owned_hover 与 native_inspect_text；若原生界面才能提供某类文案，Q-D 对该能力必须另做等价抽取资格，不能静默改交 hover。L 的 previous/next 是真实浏览动作；Q 按目录选择确切公开对象再读取，不靠遍历未授权图鉴补齐。公开 flavor/稀有度等虽未必影响决策，已属于所选详情视图时仍保留，研究编码器可明确选择不用。

### 4.2 在三种 Agent 契约中何时提供

| 内容 | AP-L / IP-L | AP-Q / IP-Q | AP-B / IP-B |
| --- | --- | --- | --- |
| 当前逻辑页可见内容、完整列表与约束 | 全给；不受滚屏限制 | 全给 | 全给 |
| 未展开的 relic/potion tooltip、卡牌额外解释 | 目录提供 focus/inspect；原生实际显示后给 | 基础给名称/当前公开概要，Inspect 后给完整当前公开详情闭包 | 当此时可无原生推进地取得时，资料包直接给对应完整详情闭包 |
| 当前页内已展示的卡牌正文 | 当前上下文正文直接给 | 同左；不人为删正文以增加查询 | 同左 |
| 牌组、战斗牌堆、地图 | 原生可打开时由 Agent 导航 | 广告当前合法 Inspect refs，按需取得 | 固定 family 按下表的适用/可取得规则自动给 |
| 已知过去但当前不可取的资料 | Agent 从自身历史记忆使用；环境不冒充当前事实 | 同左 | 同左；不暗中送一份“当前资料”缓存 |
| 未揭示的新奖励/随机效果 | 原生推进后才提供 | 同左；不允许 Inspect 绕过 | 同左；不进入自动资料包 |

### 4.3 IP-Q 的具体基础信息和 IP-B 的具体附带集合

IP-Q-v1 本文选择“小而明确的基础”：当前完整原生逻辑页内容和动作、原生此时公开的 run/HP/gold 等 HUD、持有物名称与公开计数/槽位概要、历史游标和 Inspect 目录。overlay 隐藏的战场不因“很重要”自动恢复为新当前事实；可读取时通过 Inspect 取得，否则用历史并标旧。若后续要在 selector 自动附带战场，则形成新的 IP-Q 配置，这正是旧 C-H 应在的位置。

IP-B-v1 固定集合如下，不让执行器按“估计对模型有用”临时挑选：

| 当前原生阶段 | 自动附带 family | 没有附带的原因如何表达 |
| --- | --- | --- |
| 全部可决策阶段 | 当前页/HUD；当前持有卡组；当前持有遗物/药水的公开详情闭包；此时可查的公开地图 | 每项都检查此刻原生可取得条件；不可得标 native_unavailable，不沿用旧值冒充当前 |
| 战斗及战斗内子选择 | 上述＋此刻可读公开战场/状态/球＋所有此刻可查战斗牌堆和详情 | 不在战斗为 not_applicable；selector 锁住查看为 native_unavailable；实现不支持为 unsupported |
| 商店 | 上述＋已打开商店的完整公开库存/服务/报价/商品详情 | 尚未打开的商店不自动触发打开；购后未生成库存不提供 |
| 奖励、事件、营火、宝箱、牌组选牌 | 上述＋当前已揭示候选/暂选/预览/选项的详情闭包 | 未揭示组、未生成结果标 unrevealed；不得为补齐资料自动领、reroll、开箱 |
| 目标阶段 | 当前目标目录＋上述此时原生允许取得的 family | 不在目标阶段取新的隐藏伤害结果，不计算“真实结算”替代提示 |
| 终局 | 当前原生公开终局/总结与仍合法可读资料 | task-censored/未知终点不补成死亡或胜利 |

“固定资料包”固定的是**穷尽所有适用且当前可取得的登记 family**，不是保证每个阶段都有牌组和地图。`native_unavailable` 必须有原生前提证据，属于合格的明确状态；`unsupported / unknown / budget_exceeded` 是实现缺口，必需 family 存在这种状态就不能发布“完整可决策资料包”。这避免通过把缺失改叫 optional 来宣布成功。首个实现可缩小声明模式范围，但须以新身份明确，不能删掉失败样本后仍宣称此版本完整。

定义表只在该对象获准曝光时发送/引用，不能握手时预装未解锁或未揭示的整个图鉴。缓存键含游戏/内容/规则版本、locale、定义摘要；动态部分还含实例、display_context 和捕获位置。无损去重可以复用定义，但只有内容已到达 Agent 且可解析时引用才算“已提供”。分块预算和解析失败明确记录，不静默截断关联详情。

## 5. Host 侧合同与映射：不混同上层操作和底层实现

### 5.1 HC-N 与 HC-D 是能力族，不另建游戏规则

| 能力 | HC-N：原生路径 | HC-D：公开事实路径 | 共同约束 |
| --- | --- | --- | --- |
| 当前观察/目录 | 捕获确切 native owner/page/controls 的公开逻辑内容 | 同一原生观察/目录机制；不是另算一套合法性 | 完整、可绑定、执行前复验 |
| 资料取得 | 绑定 focus/open/inspect/back，捕获实际显示内容 | finite typed read，从已核对来源抽取原生此时可得内容 | 无任意 reflection、字符串字段路径或 consumer operand |
| 资料时点 | 返回每一步实际提供位置；过程可能经过多个 owner/revision | 捕获原子公开 view；多 view 需额外一致性能力 | Snapshot ID 相同而实际分开读不是同时点证据 |
| 原生执行 | 按目录投递，返回真实状态 | 仍走同一个原生执行器 | 不让 Read 成为执行旁门 |
| 连续性/事件 | 公开事件顺序、owner/代次变化 | 同左 | gap 和未知不回填 |

每个资料能力记录 `preconditions, visible_fields, ordering, source_context, effects, completeness, invalidation, qualification`。资格至少绑定游戏版本、对象族/场景和提取方式。可复用同一对象投影函数，但公平条件和当前曝光由 Connector/映射校验，不能只复用内部对象 reader 就认为合格。

### 5.2 MP-QN：一个 Inspect 怎样走原生打开—读取—返回

1. Agent 选择当前 Inspect ref。适配器核 owner/generation、控制租约和该 ref 对应的**具体、有界原生步骤模板**；模板只处理资料浏览，不做游戏选择。
2. 若所需 tooltip/页已实际展示，直接捕获，不重复打开/关闭；记录该分支。否则只提交当前目录中的原生展示操作，等待其可验证完成/owner-ready。
3. 确認打开的是预期 owner，捕获资料、显示上下文、时间/事件位置及完整性。自动发现未知子界面、必须选牌、需消耗/生成/揭示新奖励，则该能力不适合此模板，停止并报告当前状态。
4. 仅在控制仍有效、仍是本请求打开的确切 owner、返回操作当前可用时执行预定返回。不得用“全局关闭最上层窗口”清场；不返回到碰巧相似的页。
5. 核验返回的原 owner 连续性和新的 context，发布 `completed`＋资料＋**新观察/新动作目录**。不能返回旧 action IDs 让 Agent 继续提交。资料来源是捕获位置，不自动改成返回后的时点。
6. UI 已恢复只意味着恢复所约定输入位置；经过的时间、暂停/overlay 副作用和公开事件不会被回滚。若资料在返回期间过时，将其保留为历史并标 current-invalid。

**Agent 曝光规则（本候选固定为 QN-exposure-v1）：**原生 opening/captured/returning 的页面捕获和进度只进入 Host/映射法证，不作为 AP 观察、不推进 Agent 的 W。资料只有在请求的终态响应实际交给 Agent 时才曝光；成功响应含资料和返回后的观察，partial/interrupted 响应只含明确标为实际交付的那部分资料及当前可公开状态。内部捕获过但未交付的内容不属于 Agent 历史，也不能进入离线 prefix。

原生浏览期间发生的**非机械公开事件**（如已发生的公开效果、终局、接管）按该环境唯一 AP 出站顺序及时交付，不等到资料返回后倒插到过去；每条同时保留源发生位置和实际交付位置。Inspect 仍在途时 Agent 可以消费这些事件但不能并发提交 gameplay；Stop/接管走管理侧。随后到达的 Inspect 资料即使捕获更早，也只从此时进入 Agent 记忆。不同来源没有已证顺序时标 gap/关系未知，不靠墙钟拼接。原生机械开/返可在请求结果公开效果摘要中报告，但不把内部所有页面内容偷偷流给 Agent。

状态机是 `validated → opening → captured → returning → completed`，每一步可停在 `rejected_before_delivery / interrupted / delivery_unknown / return_unresolved`。模板不是数据库事务，不承诺全有或全无。

| 故障点 | 给 Agent/控制器的真实结果 | 允许的下一步 |
| --- | --- | --- |
| 打开前 stale、禁用、控制已失 | 未投递，原观察失效或操作不可用 | 重新观察；由仍有权的 Agent 决定新请求 |
| 打开结果 unknown | 不声明已读或已返回；原 request 待核 | 查原结果/owner；禁止自动重新打开 |
| 已打开但捕获不完整 | 资料 partial，记录准确缺项 | 若安全返回条件仍成立可完成预定返回并报告失败；不强称成功 |
| 返回时 owner 已变/人接管 | interrupted，保留当前真实 owner 和已捕获资料 | 不再点击返回；交给管理控制流程 |
| 返回投递 unknown | return_unresolved；可能仍在资料页 | 原请求核对，禁止自动再点返回 |

人类接管/Stop 优先中断模板；未确认可安全返回时宁可留下可诊断页面，也不擅自操作。串行一项原生 mutation，禁止 Inspect 模板与出牌并发。若未来需要读取多份资料，Q-N-v1 逐项请求；不会凭空提供原子 ReadMany。

### 5.3 MP-QD 与 MP-BD：直接读取也有必须证明的东西

当前 Read 只有 run_deck、combat_piles、shop_catalog、surface_card；并没有通用遗物/药水详情查询或公开 ReadMany。surface_card 的当前 catalog 主要覆盖 selector/reward 等 surface，并非所有战斗手牌/商店卡都能独立查询。因此下文的完整 registry 是后续实现，不是重新命名现有 API。

Q-D 在获准原生时机从 finite registry 捕获公开 view，不改变 UI、暂停或游戏状态。读之前和发布时核绑定，捕获应在受控同步边界完成；如果中途有相关源变更，返回 stale/不完整，不拼接。禁止运行未验证有副作用的属性 getter 来假装 pure。单次合法旧资料可以作为过去事实使用，但它不授权旧目录动作。

B-D 要求增加真正的多 view 一致性：在同一稳定捕获边界收集所有适用族并封存不可变 bundle，或用覆盖所有读取源的可靠变更标记验证未变化；仅对前后 Snapshot 字符串相等不够。做不到就不能发布本资料包。现有 Snapshot signature 包含 Read 目录但不含 materialized Read payload；因此这里特别要求新增覆盖详情 payload 的捕获身份/摘要或可靠变化依据，不能把现有 expectedSnapshotId 检查当成已经解决这个问题。模型收到后的世界仍可能变化，所以动作照样要 execute-time revalidate。

长列表从**已经封存的 bundle** 分块传输；不是每一页重新遍历活对象。缺任意块、摘要不符、显示内容失效都拒绝完整资格。传输可以续传同一不可变捕获，不重复原生 mutation；不能无限重新捕获直到碰巧通过。

### 5.4 可用组合与不可随意组合

| Agent 侧 ×底层 | 原生获取 | 直接事实读取 |
| --- | --- | --- |
| AP-L | L-N，本次完整候选 | 可构造虚拟呈现 owner，但新增状态机、返回/成本与 Human 映射都需另证；本轮不纳入首发组合 |
| AP-Q | Q-N，本次完整候选 | Q-D，本次完整候选 |
| AP-B | 普通逐项 UI 打开无法保证同时点和无多余效果；本次不作为合格实现 | B-D，本次完整候选，需新的 coherent bundle 能力 |

同一个 Q 实现可以按已登记 family 一部分走 HC-N、一部分走 HC-D；那是新的 MP 配置，须预先写明每个 ref 的效果，不能运行中失败后偷偷 fallback。共享 AP-Q 不意味着四舍五入抹掉底层差异。

## 6. 四案逐一的完整使用说明

### 方案一 L-N：让 Agent 管原生浏览过程

**开始：**握手满足 HC-N/OP-S；收到当前逻辑页、HUD、可用浏览和游戏动作。原生已展示什么就给什么，当前页完整候选不因屏幕大小截断。需要牌组/遗物详解时，Agent 选对应 inspect/focus/open，收到确切展示内容；原生可返回才有返回动作。

**做选择：**游戏、目标和 selector 按 OP-S；浏览中既可以按固定程序返回，也可以由模型看到内容后改成进一步查看。固定程序的每次环境反馈仍进入真实历史，不能因为没调用模型就不记录。模板不能跨未知新选择。

**结束与恢复：**每次原生步骤独立绑定/反馈；断线时恢复真实 owner 和历史，不设一个与游戏脱节的虚拟浏览栈。页面未恢复就明确在资料页。Human 导航较容易逐步对应，但 tooltip 捕获、列表完整和时机仍须证据。

**付出与理由：**复用和可审计性强；Agent/记录需处理更多页面阶段，原生 UI 成本真实存在。适用于研究“什么时候看、看完怎么办”和尽可能直接使用 native 公开边界。不能因为步骤多就预判模型一定慢或学不会。

### 方案二 Q-N：保留原生获取，简化 Agent 面前的资料操作

**开始：**收到 IP-Q 基础和当前 Inspect 目录；例如 `discard_detail@o17` 已声明会临时打开资料页/可能暂停，只能在当前阶段用。Agent 可直接做游戏动作，也可请求该资料。

**取得与选择：**Inspect 走第 5.2 节模板，成功返回资料＋返回后的新观察；Agent 不需要选择机械 Back。模板期间出现游戏选择立即停止抽象，不代选。目标/奖励/selector 的决定仍由 Agent 分步作出。

**结束与恢复：**正常完成不留下额外 Agent 页面栈；异常结果可以留下原生页面，必须作为当前恢复事实呈现，不能让 AP-Q 假装世界没变。恢复由 owning 控制流程处理；普通策略不获得任意关闭窗口能力。

**付出与理由：**避免新增全部直接抽取来源，同时把机械导航移出模型选择空间；很适合先验证“一次查询”需求。代价是有界流程/恢复比 L-N 更复杂，原生 UI 开销未消失，而且不支持在已经同意的机械返回之前让模型临时分支。若用户主要需要 Human 浏览策略研究，L-N 更直接。

### 方案三 Q-D：用经过验证的公开读取实现同样查询

**开始与选择：**AP-Q/IP-Q/OP-S 与 Q-N 一致；同一资料需求表现为相同 Inspect。具体 Host 能力声明为 pure，读取来源、排序、动态显示和原生可取条件均注册。

**取得与恢复：**成功返回状态绑定的资料；没有 native open/back 步骤。stale 返回后重观察，不能假装资料仍当前。无副作用读的重取可由 Agent 新决定，或按已声明 bounded read retry 合同进行；这不授权重新投递任何 native 操作。

**付出与理由：**有机会减少 UI 状态变化、界面时机依赖和恢复故障面；同一提取函数可服务 B-D。成本在于逐对象族证明公开内容、当前可得条件、没有隐藏顺序、getter 无效果，并在游戏更新后维护。缺原生同一时点对照时不能发布该能力；不以“字段能读”替代资格。

### 方案四 B-D：固定公开资料包，Agent 直接作游戏选择

**开始：**核对 IP-B 和原子捕获能力；每个 owner-ready 发布一个完整 bundle 和 OP-S 目录。所有定义引用可解析、必需块已交付后才调用 Agent。未启用 Inspect，不能临时因为包小了就让模型访问另一套资料 API。

**取得与选择：**每次新可决策位置重新生成当前合法资料包，稳定定义和未变内容可无损去重；取消、奖励重访、selector 子决策也一样。暂不可读项有明确状态，历史仍由 Agent 维护；不能因此声称 M2 已无用。

**结束与恢复：**断线核 bundle/cursor 和 Agent 状态连续性；缺口显式 segment。资料捕获不全就是未能准备当前输入，不允许给少半个包继续跑并把结果计入同一完整 profile。

**付出与理由：**便于把研究问题限制到“已给资料后怎么选择”，不要求从缺乏 Human 查询标签的数据先学会查询策略。增加捕获/编码/记录量和同时点证明负担；还可能改变原本依赖记忆的信息条件。因此它是研究条件的一种选择，不是天然更公平、更聪明或更易迁移。

## 7. 全游戏逐场景规则：不是只解决查牌堆

以下 OP-S 与原生行为四案共用。L-N 用真实展示提供额外资料；Q-N/Q-D 用 Inspect；B-D 按 IP-B 自动附带。所有“可查”均以当前原生可得条件为前提。

| 场景 | 当前必须准确表达/允许的原生操作 | 额外资料差异与关键不能做的事 |
| --- | --- | --- |
| 开局/角色/模式 | 任务管理选择合法起点；若任务包含前台角色选择则逐原生页；开局产生新 generation | 不向 Agent 泄露私有 seed/未来布局；本局运行不能直接请求 reset 来逃避失败 |
| 地图 | 已公开地图与当前可走目录分开；选节点、等待 travel 与到达 | L 原生地图流程，Q 可查公开地图，B 条件附带；看到节点不等于可走，不预知房间随机内容 |
| 普通/目标出牌 | 手牌/费用/资源/意图/合法选择；choose card、target、cancel、效果等待 | 未发生抽牌/生成结果不能预送；把 hover 伤害说明当原生描述，不当执行保证 |
| EndTurn/敌方过程 | 仅原生允许时结束；等待自动效果、新回合/owner | 中途公开事件可入历史，不每个 poll 调一次模型；不抢敌方进程发动作 |
| 药水 | 当前 slot/状态，popup 的 use/discard/close，target/cancel | tooltip 走各案资料方式；popup 消失不证明使用/消耗，不能 Inspect 偷用药水 |
| 手牌选择 | 完整候选、已选、max 替换规则、确认/取消的实际可用状态 | 额外战场 Q 需请求、B 条件附带；不套用 grid 满额规则 |
| 生成牌/simple grid | 真实候选、opening ready、toggle/confirm；退出可能 Task canceled | 不靠固定 sleep 宣告可用，不提前给生成结果；零选与取消分开 |
| 抽/弃/消耗堆选择 | pile 来源、完整逻辑候选、有效 min/max、动态已选清理、自动完成条件 | 查看牌堆与从牌堆选择是两种能力；不能把 Inspect 当 selector 或替父动作完成选择 |
| 牌组升级/移除/变换/附魔 | selecting/preview/confirm/preview-cancel/whole-close 的原生区别 | 预览使用派生对象显示但选择绑定原对象；不得让 preview clone 成为 operand |
| 多层 selector | 当前 child 目录和可证 parent relation；父请求等待、child 完成后原生续执行 | parent_observed 不能变 parent-await；资料可得性逐层检查，不借上层仍可读来跨锁 |
| 外层奖励 | 独立组/linked group、已解决/未解决、open/claim/proceed | 未打开组的真实新揭示不归纯查看；B 不能展开全奖励偷看 |
| 卡牌奖励/重访 | 当前候选、真实 alternatives、可选次数；返回外层、reroll、领取、特殊消耗分别表达 | 原生 Skip 不一定完成奖励；reroll 留当前；特殊替代可能完成并触发新效果 |
| 商店开/购买 | 当前公开目录/价格/资源；native open、buy、close/proceed | 不自动执行开店或购买来补资料；补货/Hook 后必须新观察，不能用旧价绑定 |
| 商店移除 | 服务入口→选牌→preview→confirm；最终 native 返回后才以实际事实确认扣费 | 看牌组可以 Inspect；选要移除哪张必须 Agent 决策；取消预览不等于退出店 |
| 事件 | 当前文本/公开选项/禁用原因，选后可能 combat/reward/新 option | 事件内部战斗结束可能回事件，不能硬编码 map；下一随机页不在资料闭包 |
| 营火 | 当前原生选项；升级/挖掘等可能子流程；完成后重读剩余选项 | 不能选一次就强制结束；未生成挖掘结果不能查询 |
| 宝箱/遗物选择 | open chest、普通/额外 reward、relic collection、skip/proceed 的实际阶段 | 不能为自动资料包提前开箱；提示预览、已持有遗物、待选新遗物身份分开 |
| 跨幕/连续自动推进 | readiness 请求、原生等待、新 owner/act entered 各自记录 | 请求后画面不变不重发；父事件、第二 Boss、map 路径由原生决定 |
| 终局/放弃/退出 | native win/loss/abandon、task stop、结果未知分开；summary 原生操作 | 断线不是输，人工接管后赢不是 Agent 自主赢；新局不续用旧绑定/W |
| 教程/未知 overlay/模式差异 | 有注册的 modal 才有确认操作；未支持 owner 进入 gap/交还 | 不能默认关闭所有遮挡，不能发坐标兜底；多人 vote、实时暂停规则另设配置 |

这一表覆盖已识别机制，不承诺穷尽所有卡/遗物 Hook。某 Hook 引入新原生行为时先判断是否落在已资格化机制内；否则报告 unsupported。四案不会因为信息接口完整就自动修好底层当前 selector 差异。

## 8. 统一异常、控制与恢复表

| 情形 | 四案共同处理 | 特有影响 |
| --- | --- | --- |
| stale/catalog/代次变化 | 提交前拒绝；新观察重新选，不搬旧 ID | Q 的响应与 B 的 bundle 都可能成为历史；L 当前浏览 owner 也需重新绑定 |
| duplicate observation/event | 去重，不重复推进 W | 重访 occurrence 不同必须保留；相同正文不去掉真实重访 |
| native delivery unknown | 冻结依赖提交，查原 request/attempt，保留未知 | Q-N 开/返两个阶段分别核对；不能重跑整个模板 |
| 纯 Read 超时/传输断开 | 只按已声明无副作用/不可变内容合同重取或续传 | Q-N 不是纯 Read，不能套这个重试规则 |
| 不完整候选/未知详情类型/超预算 | 标准确缺失；required 内容不足就不给完整输入资格 | B-D 对整个必需资料闭包负责；L/Q 若当前决策必需内容缺失也不能装完整 |
| 父请求等 selector | 处理确切 child，父请求不重发 | 子交互本身能是 Agent 决策；因果记录与训练样本资格分开 |
| empty/null/Task canceled/退出 | 保留实际原生含义，不统一成“成功取消” | 浏览返回只退出资料；selector 的取消可能结束原生效果 |
| Stop/人接管 | owning Runtime 先撤销 Agent 后续提交权，记录实际停止与原生进行中事实 | Q-N 不再安全时停止返回；不能为了页面好看继续发点击 |
| 断线恢复 | 校验环境/actor/AgentSpec/状态格式/游标和连续历史 | 相同页面不能证明 W 正确；缺口就 reset/new segment 并在评价中记介入 |
| Host 能力变化 | 拒绝旧配置的新工作；记录新身份/资格 | 禁止 Q-D 失败后未声明转 Q-N 或 B 缺字段转 Q |

请求账本和实际观察用于恢复，不能靠轮询间隔、FIFO、最新 root 或“下一次 Human action”回填因果。跨 producer 的关系需要明确来源；墙上时间仅作时序辅助。

## 9. 四段贯通例子

### 9.1 同一任务：看弃牌堆和一个已持有遗物，再出牌

共同起点：同一可交互战斗位置，两份资料此时都合法可得，OP-S 相同。仅为说明操作，非运行实测。

```text
L-N: O0 → OpenDiscard → O1(牌堆) → Back → O2
         → Focus/InspectRelic → O3(详情) → native退出提示/页面 → O4
         → ChooseCard → [Target/Cancel] → 原生效果/子选择
Q-N: O0 → Inspect(discard) → 内部Open/Capture/Back → O2＋带来源的牌堆
         → Inspect(relic) → 对应原生模板 → O4＋详情 → 同一游戏选择流程
Q-D: O0 → Inspect(discard) → 绑定资料
         → Inspect(relic) → 绑定详情 → 新鲜观察/目录 → 同一游戏选择流程
B-D: O0(已含此时完整资料包) → 同一游戏选择流程
```

遗物如果只有 focus tooltip，退出不一定是一个 Back 页面动作；映射按真实机制登记，不能为了凑动作数统一为 open/back。若 Agent 已决定两项都看，L-N 可固定完成上述浏览后只调用一次选择模型；Q 的两个 Inspect 也可由 Agent 内固定输入组件发出。模型调用量、W 消费量、协议操作量分别计数。

### 9.2 打牌触发弃牌堆 selector

四案都必须：初始选择出牌→原生接受/效果进入 child→收到完整 child 候选/已选/pile 来源→Agent 选牌→原生确认/自动完成→父效果继续→公开新观察。不能事先把尚未曝光的 child 列表装入出牌输入。

L-N 如需额外战场信息走真实可用查看；Q 发此时有资格的 Inspect；B 仅在该 selector 时刻合法可得时附带。选择绑定来自 selector 的 action catalog，绝不来自之前 Inspect 返回的普通牌堆对象列表。父子 exact relation 不可得时记录较弱关系/未知，不假装 parent-await 已证明。

训练端可以形成出牌与 child 选择两个条件决策，但前提是各自输入/动作/时点/曝光有资格；Annotator 的一个 root＋continuation 结构本身不自动提供第二个 N 样本，更不能填成 `PlayCard(以后才知道的selected_card)`。

### 9.3 卡牌奖励看过、返回外层、再次进入

四案均把打开奖励视为可能揭示/推进的原生操作，不能当纯 Inspect。进入后有当前候选，Agent 可以合法返回、reroll、领取或执行特殊 alternative，依据真实语义。

第一次返回后，再进入即使卡牌文字相同也是新的 occurrence。记录第一次看过和返回的历史；D-M2 可消费该历史，环境不强制它记住或推断“已经拒绝过”。Q/B 的资料取得方式不能消除这段决策经历。是否能最终永久放弃由原生外层流程决定，不把内层 Skip 直接标“放弃所有奖励”。

### 9.4 查资料时人接管

L-N 已打开资料页：Agent 停止，真实页面仍在，Human 接管。Q-N 已捕获还未返回：撤销后不再返回，响应 interrupted，资料属于先前曝光位置，模板保留当前 owner。Q-D 捕获若已经封存可记录为已取得过去资料，若未完成则失败；B-D 未封存完整包不发布可决策输入。四者都将介入从 autonomous run 评价中分离，不靠恢复成功洗掉中断。

## 10. 记录、旧数据转换和 D-M2 接入

### 10.1 记录四种不同事实

1. 原生/Host 法证：真正原生操作、owner、已证 Commit/continuation/后继及未知；保留原 authority。
2. AP 曝光日志：哪份观察/详情/历史何时实际送达 Agent，引用内容摘要和来源；实际收到不等于模型已有效理解。
3. Agent 日志：固定程序或模型提出的请求、输入表示/状态游标、实际反馈、推理成本；绝不能把 Agent action 标 Human。
4. 任务/研究：控制介入、资源、终点、数据用途/划分、训练标签资格；不混进当前策略输入。

Q-N 一个 Inspect 可以对应多项 Host 操作，保留 child request 关系；L-N 每步都有 AP event；Q-D Read 无 native Commit；B-D 捕获日志不是“Human 主动查看过”的证明。记录内容可去重，但来源/曝光位置不能去掉。模型输入和法证字段采用明确 allowlist，私有 seed/lease/内部 witness 不因为存在于同一 JSON 就进入编码器。

### 10.2 三种目标轨迹的转换条件

| 目标 | 需要什么证据 | 不能捏造什么 |
| --- | --- | --- |
| L-N | 原生展示/操作/返回的实际顺序、相应公开内容和完整目录 | 缺 hover 记录不能补成 Human 看过 tooltip |
| Q-N/Q-D | 对应资料在目标时点可取得、内容和曝光顺序可证明；折叠原生步骤有映射规则 | 可以生成标 derived 的 Inspect，但不能当 Human 原本发过这个请求；不能抹掉原生中途游戏选择 |
| B-D | 每个目标决策位置的 IP-B 同时点资料和 availability 证据 | 后一时刻才读的牌组/遗物说明不能回填前一时刻；现在游戏能读不证明旧记录当时捕获过 |

转换报告逐段列可用/拒绝分母、原始引用、省略步骤、派生操作、缺失和 actor。可用于局部 N 不等于合格 M2 连续 prefix，更不等于可重放的全局轨迹。旧数据不足可导致新用途零条合格；原件保留，用途不自动扩大。

### 10.3 封装 D-M2 的具体适配

事件适配器按选定 AP 的真实曝光顺序串行消费输入，以明确事件 ID/cursor 去重。状态 writer 接受当前合法输入、之前实际请求和已实际提供的公开反馈；候选分支评分只读 W，未选预测不写 W。每个事件是否写 W、是否调用昂贵 scorer、是否有 N 标签分别规定，不把“一个环境请求”硬等同“一次模型推理”。

本次参考 Agent 固定采用以下 **event-consume-v1**，避免“实现时再定”。环境的 AP 曝光顺序先确定，Agent 再按表更新；别的 Agent 可采用不同内部设计，但必须有新的 AgentSpec，并不能混用状态回执。这里的一次 W 更新表示调用一次已登记的状态消费入口；是否包含昂贵网络以及实际耗时另计，不把它当免费。

| 实际收到的事件 | W 更新规则 | scorer 是否调用 | N 标签资格 |
| --- | --- | --- | --- |
| 新初始观察/真实新 owner-ready/重访 | 每个新的语义 event ID 一次；重访正文相同也更新 | 输入完整且有 Agent 待决定请求时调用；固定程序接管该步则不调用 scorer | 只有合格实际 choice；观察本身无 N |
| Inspect 或 action 发出 | 当时不额外更新；将实际已发请求登记到 pending history，下一条入站语义事件作为 prior actual 输入一次 | 本次选择已经结束；固定程序发出也记录来源 | 预测前不可使用当前选择 label；实际选择可作其原决策位置 target |
| Q 的 Inspect 终态响应 | 实际交付的资料/失败/状态与结果中附带的新观察组成一个 AP 语义事件，更新一次；按 source 标旧但不倒插 | 仍有控制、资料/目录合格且下一步需模型决定时调用 | learned Inspect 的选择可有对应 N；派生/固定查询不能冒称 Human 标签 |
| L 原生浏览步骤的公开反馈 | 每个实际新展示/返回事件一次；同一消息中的 result/observation 合并消费 | 可由固定浏览程序继续，所以不必每次 scorer | 有合格 Human/指定示范行为才有 N |
| Q-N 内部 opening/capture/return 进度 | 不进入 AP 曝光，零次 | 否 | 无 AP N；保留底层事实用于审计 |
| 公开自动效果/continuation | 按实际交付顺序每个新语义事件一次；父/child 关系只用已公开且有资格的部分 | 无待选目录时不调用；child owner-ready 可触发新决策 | 自动事件无 choice 标签，但保留在 prefix |
| stale/rejected/公开失败结果 | 新结果事件一次，含前一实际请求；尚未新观察时不选旧目录 | 待新鲜完整输入后才可调用 | 不能把拒绝结果当成功动作标签；保留有资格的原选择及负结果 |
| 重传、重复 Observe、心跳、纯传输进度 | 零次；新真实 occurrence 不在此类 | 否 | 无新增标签 |
| gap/新 generation/无法续接的接管 | 结束旧 segment，明确 reset 一次；新初始输入另更新一次 | 管理允许恢复且新输入合格后 | 连续 prefix 跨 gap 不合格，不能靠 mask 一步假装修复历史 |
| 终局事件 | 新终局公开事件一次，之后冻结该 segment | 无后续策略决定则不调用；若任务包含 summary 导航，仍用目录 | 终局无 choice N；Z/O 由独立终点证据决定 |

同一 action result 与它携带的 observation 在序列化时使用一个 AP event ID，不能双写；独立之后观察有新的真实事实才是新事件。pending actual request 在下一次 consume 后清空其“未消费”标记，后续反馈引用同一 request 但不重放已消费请求。没有后续入站事件就只留下未闭合记录，不捏造反馈。重新绑定但语义未变的传输消息不写 W；原生真实页面重访是语义事件，二者靠 occurrence 而不是正文哈希区分。固定浏览程序也必须走此消费入口，不能跳过输入使在线/离线前缀不一致。

| 方案 | D-M2 需要学/执行什么 | 时序 N 的主要资格问题 |
| --- | --- | --- |
| L-N | 浏览和游戏请求；或 AgentSpec 固定浏览程序＋模型游戏选择 | 要有浏览序列/曝光历史；无 N 的合法事件仍需更新 prefix |
| Q-N/Q-D | 选择 Inspect 或游戏请求；也可先固定一个登记的查询策略 | 旧 Human 不提供天然 Query 标签；固定策略可以构造 derived 轨迹但不伪称 Human 查询监督 |
| B-D | 在资料包上选择游戏动作，保留奖励重访/子决策等历史 | 每个位置的包须合格；不能拿资料不全的旧 N 行拼出完整序列 |

首次对比可给 L/Q 使用相同固定资料需求程序，排除“是否学会查询”的变量；之后再研究 learned inspection。这是**实验设计建议**，不替用户锁定 AgentSpec。现有 light-action M2 kernel 有复用价值，现有 Public M2 port 拒绝 Read、prior action/feedback 不足，不能原样声明支持新四案。新 adapter/表示/数据/recipe 要有新身份并验证在线与离线 prefix 一致。

sequence-N 优先；Z/O 后续按实际分支和合格 horizon 引入。原生主动出牌数与协议导航/Inspect/模型调用数独立；不能因为 B 的请求少就标成更强策略。胜利、真实失败层、战斗末 HP、剩余主动出牌是独立预测目标，不把早死少操作自动变成高效用。

## 11. 成本怎样公平比较，以及现在不能承诺什么

**撤回以前从合成表推出 C-H 优先的论证。** 那张表中 query 没有自动附带 selector 战场，而 C-H 有；C-L 每次开/返还假定额外 policy 调用。它比较的是特定信息配置和执行程序，不能证明独立协议优劣。旧源码/JSON 回执保留作历史，原始数值不被重写；其模型调用数是输入假设，不是实测。

后续最小比较分三组，不把所有变量揉成一个胜率表：

| 组 | 固定什么 | 只改变什么 | 能回答什么 |
| --- | --- | --- | --- |
| 获取实现比较 | AP-Q、IP-Q、OP-S、同一 Agent 固定资料需求/内容、匹配起点 | MP-QN/HC-N 与 MP-QD/HC-D | UI 状态、失败/恢复、总耗时和维护差异；不是学习优劣 |
| Agent 接口比较 | 相同合法资料需求/内容、OP-S、相同选择器与推理程序 | L 的显式操作、Q 的一次请求、B 的自动提供 | 协议步骤/记录/编码成本；B 额外曝光须匹配或明确另报 |
| 研究效果比较 | 固定训练/评价划分、预算、任务/种子分组、表示和容量 | 完整 AP/IP＋查询策略/记忆实验 | 整个 Agent 系统的任务表现；改变信息条件时不能归因于 M2 本身 |

场景至少包含小/大牌组战斗、动态遗物/关联预览、被 selector 锁住的资料、奖励重访、商店移除、长关联/超限目录、UI 返回中断与终局。真实原生不可复制时不宣称严格配对；报告匹配条件和顺序偏差。用独立 run/combat 分组，不将同一轨迹每个前缀当独立样本。

分别测：协议请求数、native UI 操作数、view 捕获数、资料/目录字节、实际 tokenizer tokens、编码/状态更新/scorer 调用和时间、网络/原生等待/记录时间、端到端 p50/p95、缺失/失效/未知/介入次数、内存与吞吐。缓存命中、压缩、详情规模、异常尝试均计入，不能只报成功路径；导航固定程序与逐步模型决策分开列。

当前没有这些真实延迟/故障率/策略质量测量，没有任何方案已经胜出。源码可以证明状态机不同、某项能力已有基础，不能证明工时、毫秒或胜率。也不必先建设四套完整产品：先做共享捕获、忠实最小机制和候选 adapter 的有界对照即可筛掉不满足合同的组合。

## 13. 逐项验收与实际选择办法

| 验收项 | 最小正例 | 必须拒绝/保留的反例 | 适用组合 |
| --- | --- | --- | --- |
| 身份与能力 | 同一登记配置成功握手 | missing view、不同 OP/profile 被静默接受 | 全部 |
| 当前公开详情 | 同名两个实例费用/计数不同，分别正确 | 隐藏 relic counter、基础描述冒充动态、preview 当手牌 | 全部 |
| 关联完整性 | 关键词/预览闭包可解析、循环引用有限 | 未知 tooltip 或超预算被截掉却标 complete | 全部 |
| 完整逻辑目录 | 超屏候选/长商店全部可表达 | visible holders/top-k 当完整目录 | 全部 |
| 原生约束 | hand replace、grid cap、min0/空/自动完成忠实 | 用 raw prefs 算“应该可确认”，忽略 native controls | 全部 |
| 揭示时机 | 进入 reward 后才给候选 | Inspect/Bundle 提前开箱、reroll、生成奖励 | 全部 |
| 时间绑定 | 每份 view 有真实捕获和失效位置 | 旧手牌＋新牌堆＋旧 action catalog | 全部 |
| 浏览恢复 | 打开、捕获、确切返回、新观察 | 人接管/owner 变化后仍点 Back；返回 unknown 重发 | L-N/Q-N，Q-N 逐状态注入故障 |
| 纯读资格 | 同条件原生展示与 typed Read 对照 | getter 有效果、排序泄露、原生禁止时仍可读 | Q-D/B-D |
| 一致包 | 多 view 同时点封存并无损分块 | 前后 ID 同名但源已变；缺块仍推理 | B-D |
| parent/child | 真正 child 决策和父续执行记录 | latest-root/FIFO 后补，父重发 | 全部 |
| 状态/记录转换 | 在线与离线同 prefix；实际曝光可查 | 重传双写 W、未来 label/晚读资料回填 | 全部 |
| 成本与评价 | 固定程序和真实 scorer 次数分别记录 | 把每次 API 调用当昂贵模型调用；少请求等于好策略 | 全部 |

门顺序：源码/忠实可移植反例→相应 exact-game build→授权后的最短原生资格路径→有身份的 Agent/记录闭环→匹配成本/研究评价。能共享的检查只做一份共用机制验证，各 MP 专有状态仍单测；不要复制四套相同生产测试，也不能共享一次成功就跳过不同实现的专有故障。

具体选择取决于优先目标：若先要原生对应与浏览行为，选 L-N；若要一次请求且主要复用原生，选 Q-N；若已有可验证直接读取、重点是查询策略和较少 UI 副作用，选 Q-D；若先固定信息条件贯通 D-M2 N，且具备一致捕获和数据来源，选 B-D。**这是条件性选择规则，不是本轮替用户接受默认。**

G1 需明确接受一个完整组合或有据修改，连同 AP/IP/OP/HC/MP、模式范围、详情族、必需/不可得规则、状态更新/记录转换、性能预算和资格门。所有候选已经给出具体初始答案；未测量值和未实现资格留给明示检查，不能写成“实现时自行决定”。下一实施包仍沿用既有 P/E/G/V/R 任务编号。
