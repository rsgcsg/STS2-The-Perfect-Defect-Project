L-N 首版进一步收敛见[具体规格](BASELINE_LN_V1_SPEC.zh-CN.md)：合法集合由 Connector 完整持有，不强制每个模型全量打分；新增模型无关端口是提案，不改变现有 scorer schema。

入口：[上层基础](BASELINE_FOUNDATION.zh-CN.md)、[P4 学习与工程连接](BASELINE_DATA_AGENT_CONTRACTS.zh-CN.md)、[任务表](../plans/BASELINE_TASKS.zh-CN.md)。本文的候选名称只用于本次设计比较，不替换原生协议、text-menu 或已训练模型的身份。

## 1. 服务对象、范围和设计空间

交互环境要使 Agent 在声明的原生玩家信息边界内解决完整游戏任务，允许研究信息表达、历史与模型的影响。当前设计调查覆盖 SC-01–10 的游戏过程，SC-11–16 的采集、学习、任务和分发接口由 P4 接续。首发游戏版本、角色/模式、必需能力集合及成本阈值由 G1 明确；不将未支持的格子删掉来宣布完整。

抽牌堆的真实打开、虚拟查看、直接提供是局部机制，**不是完整协议，也不是只能三选一**。完整候选必须同时规定信息时机、刷新、操作粒度、输入 owner、嵌套、历史、恢复、记录转换和成本。允许进一步产生不同候选，但新增候选必须填满这些维度。

| 设计轴 | 可比较选择 | 约束 |
| --- | --- | --- |
| 公开信息提供 | 当前逻辑页、显式资料操作、规定信息集自动提供、经论证的组合 | 保留获取时机/成本，不能提前生成或泄露隐藏信息 |
| 操作粒度 | 确切完整意图、语义分步选择、现有原生未完成阶段 | 中间存在新信息/效果/选择时不能盲合并 |
| 协议呈现状态 | 原生当前页、协议工作区、无页面的结构化上下文 | 状态 owner、失效和恢复必须单独说明 |
| 历史与反馈 | 有序公开事件、可重放片段、明确输入-only 限制 | 内容相同不等于同一次发生；不声称知晓 Human 心智 |
| 表示成本 | 结构化共享字段、无损引用、批量/流式传输、模型内压缩 | 环境目录完整性不受模型 token 上限反向裁剪 |
| Host 实现 | 原生窗口、受资格化的 Managed、其他实现 | 接通 schema 不等于行为等价 |

当前比较改按 Agent 契约、Host 能力、映射规则分别识别。C-H 只是查询方案的自动附带 view 配置，撤回将它算作独立协议的分类；也撤回从旧合成 fixture 推出 C-H/C-S 优先的论证。以下 C-L/C-S 是早期设计用语，不能替代新文档逐项规定的 AP/IP/OP/HC/MP 身份。

## 2. 候选 C-L：以原生逻辑过程组织的交互

- 观察对应当前确切原生逻辑页/输入 owner；投影完整逻辑列表，去掉坐标、滚轮等设备细节，不只截取当前屏幕几张牌。
- 原生可以取得的信息通过相应原生查看/返回语义获得；保留时机、暂停、遮挡和控制条件。不因 Host 技术上能读取而免费提前提供。
- 普通动作只有在中间没有独立信息、效果或有意义选择且确切绑定成立时，才允许将机械步骤组成完整意图；已存在的原生未完成选择阶段须明确表达。
- 协议不新增虚拟资料页栈；其状态跟随原生页和子选择。当前模式改变即更新有效绑定。返回、取消暂选、取消效果和最终放弃分别定义。
- Agent 接收真实公开事件，自己决定是否及如何保留历史。原生查看增加交互阶段，但不必增加昂贵模型调用；Agent 可用固定程序浏览，状态消费、协议操作和推理分别计量。
- 断线后只能在证明原生连续性及可恢复公开历史时继续原 Agent 状态；否则按 P4 的中断/重置规则处理，不能用相同画面猜连续。

优点是原生 Human 轨迹的映射通常较直接；代价是信息取得操作多、Host 呈现依赖较强。它也不等于鼠标像素模仿或完整原生等价，仍须逐机制验证。

## 3. 候选 C-S：语义决策上下文与声明的信息能力

- 观察提供当前问题、必要公开上下文和完整有限操作目录；公共 HUD/当前选择约束等基础事实在 profile 中列明，不依赖猜测“重要”。
- 另有有限、类型化的信息能力目录。最新 AP-Q 的 Inspect 可映射纯 Read 或有界原生浏览：前者不改变 UI，后者必须声明 owner/暂停/中断效果；两者不能因上层只有一次请求就混同。详情见新文档的 MP-QN/MP-QD。
- 必须真实打开、生成、支付成本或改变机会才能揭示的信息，仍通过原生操作发生，再形成新的观察；不能把它塞进纯 Read。
- Agent 可以由模型决定 Read，也可以由其封装内部已登记的输入组件按固定规则取信息。两者都是不同 AgentSpec，须记录实际请求与信息曝光；runner/GUI 不得在外部偷偷预读或代选。
- 普通确定意图可直接选择确切 card/target 组合；真实子选择器仍是新的交互，执行器不代选。此规则不允许跨新揭示信息预先选择未来操作。
- 公开历史自动作为环境可提供的事件接口；模型怎样消费由 P4 定义。协议不强制 latent slots、完整历史文本或固定 previous-action 特征。

### 早期 C-S 的信息配置不能偷偷改变题目

第一版设计给出两个可实例化配置用于 P5 对比，未确定默认：

| 配置 | 外部信息含义 | Agent 操作/成本 | 记录要求 |
| --- | --- | --- | --- |
| C-S-query（早期） | 基础上下文＋当前合法资料请求；调用后信息才提供 | 记录信息请求、响应、延迟和推理次数 | 每次提供及其当前绑定，查询失败不伪造成功 |
| C-S-bundle | profile 声明的必需公开 view 集自动取得并一并提供 | 不存在取得这些已附带 view 的策略动作；内部采集成本另计 | 每个决策位置都有全套 view 的同时点依据 |

其他虚拟工作区、选择性聚合或分步方案仍可作为候选，必须给出完整状态和转换规则。不能在运行中因某 Host 不支持查询，就静默退化为另一配置。组件缺少必需能力应明确拒绝该 profile，或使用另有身份和评价条件的降级方案。

不同配置下操作次数和信息曝光不同，不直接作纯模型/记忆消融。无损引用只减少重复字节；在声称信息已提供的边界，Agent 必须已经能够实际消费它。模型选择进一步压缩属于 Agent 的能力/成本，不改变环境事实。

## 4. 信息能力登记表与公平边界

每个 fact family 必须有一行可审查定义：公开内容、可获得条件、确切原生依据、源事件/状态位置、对象/顺序含义、有效期、提取副作用、缺失原因、对应记录、字节/token/调用/时间成本。列名是设计要求，不是已存在的 wire。

| 信息族 | 必须表达 | 不得附带/冒称 |
| --- | --- | --- |
| 战场/手牌/资源 | 原生公开值、当前说明、对象与当前选择 | 未公开敌方内部计划、RNG、未来效果 |
| 牌组/各战斗牌堆 | 公开可见成员、多重性、牌的公开状态与 pile 语义 | 从底层数组顺序导出真实抽牌顺序 |
| 已知置顶/历史揭示 | 有来源的公开事件或可验证推断，注明 derived | 把隐藏牌序称作“玩家可以推断” |
| 地图/持有物/说明 | 该位置合法可取得的公开资料，动态显示值有绑定 | 未揭示事件或未来奖励 |
| 选择器/奖励/商店 | 完整逻辑选项、min/max、已选、可确认/取消、当前资源限制 | 只看 visible holder 就宣称完整；把随机选项结果提前算出 |

可取得条件必须检查原生正等待选择、动画推进、信息页暂停、房间变更等情形。合法公开集合不等于所有时点都可无副作用取得。概率估计来自模型/允许规则推断时应标为估计，环境不因能读隐藏生成器就提供本局未来答案。

## 5. 共用消息与身份语义草案

实现可采用库、HTTP 或其他运输层；以下规定消息含义，不强制服务拆分或承诺旧 SDK 兼容。

| 消息 | 必需含义 |
| --- | --- |
| Describe | protocol/profile 身份、信息策略、操作/Read 能力、世界目标、Host 支持与限制、历史/恢复能力 |
| Observe | observation 身份、环境 generation、有效 context revision、当前交互/输入 owner、公开内容及缺失、完整 catalog 与 digest、当前 view/Read 描述、事件游标 |
| ReadRequest/ReadResult | request ID、依据的 observation/context、目录内 query/ref、结果来源/完整性与是否仍有效；不得带任意反射或原生操作数 |
| ActionRequest | request ID、依据的 observation/context、完整 catalog digest、选中的 action ID；控制权另放控制 envelope |
| ActionResult | accepted/rejected、delivery、原生 Commit 的已知状态、公开后续观察、子交互或等待信息；unknown 明确保留 |
| Events | 有身份的公开事件与 producer 顺序、已证关联、可用位置、gap/takeover/reset/terminal 标记 |
| Control/HostManagement | claim/release/stop、开局、场景、关闭与受支持恢复；不进入普通策略权限或模型特征 |

P4 的模型输入不包含私有 lease、源文件路径、随机种子、内部类型名等控制信息。公开对象关系可用一致的局部别名表达；不能删除对象同一性，也不能借随机句柄携带隐藏状态。

协议的法证/控制回执与 Agent-facing 公开反馈分通道。原生 Commit、内部 parent-await 证明等可由 Recorder/Runtime 保存，但不能因字段存在就提前暴露给模型。Agent 只得到自己请求的公开状态和按信息策略已可提供的结果；训练端可以用更强证明建立 target mask，不将证明中的私有事实输入策略。

### 三种进度不要合成一个 success

1. 请求进度：被拒绝、未投递、已投递、投递未知。
2. 原生过程：已知 Commit、等待子选择、续执行、可交互 owner、未确认完成。
3. 任务结果：胜负、进度、成本、接管/删失，由任务/评价解释。

副作用也可多维存在：一次原生查看可能改变 UI 并暂停战斗。不要用互斥标签掩盖复合效果。即时后续观察不是因果 settled successor；Finished、队列空、时间过去或轮询不能升级证据。

## 6. 连续性、嵌套和恢复

- 观察内容改变、context revision 改变、事件发生、新局是不同事实。重复 observe/事件重传不自动推进模型状态；真正重访即使内容相同也是不同事件。
- 纯 Read 绑定有效位置。读取期间状态改变，响应应注明失效或重新捕获；最终动作重新绑定，不复用旧 action ID。合法过去信息可以保留为历史，不能冒充新状态。
- 相同 request ID＋相同请求返回已记录结果；冲突内容拒绝。未知原生投递只允许核对原请求，不生成新 ID 重发。纯读取/内容传输的重试按各自无副作用/幂等契约处理，不一概等同原生重试。
- 父动作进入确切子选择时，父请求保持等待，Agent 能处理子目录；不重复提交父动作。child→parent-await 关系需要确切来源，parent_observed 不能冒充已证明关系。
- 子选择完成后仍等待实际原生续执行/新 owner；一次确认投递不等于父效果完成。取消暂选、取消整个原生效果、暂离奖励、最终放弃必须使用各自真实语义。
- 实例/运行代次改变使旧控制、观察和动作句柄失效。恢复 Agent 状态须匹配模型/表示、历史游标和环境连续性；不满足则显式新 segment，不能宣称无缝继续。
- 事件可以重复运输，逻辑消费通过 ID/cursor 去重；缺口显式报告。不要承诺无法证明的分布式恰好一次。跨 producer 不用时间戳强造全序或因果。

## 7. 全游戏场景如何落入同一候选

| SC | 共用交互规则 | C-L / C-S 差异与必需反例 |
| --- | --- | --- |
| 01 开始/地图 | 管理起点与 gameplay 分开，公开可走目录，代次与终态明确 | 地图资料取得方式不同；旧节点请求不得作用新局 |
| 02 战斗/药水 | 完整当前动作、确切 card/target/slot、原生复验、资源与等待 | C-L 原生逻辑上下文，C-S 基础＋view 策略；不靠模型猜合法性 |
| 03 信息取得 | fact policy、提供时刻、成本、失效都有记录 | 三种牌堆机制只是局部选项；不额外泄露数组真实顺序 |
| 04 选择器 | 候选/min/max/暂选/确认/取消，parent-await 与真实续执行 | 逻辑列表须完整；零选/零 holder、超屏列表、取消后父过程分别验证 |
| 05 奖励 | 打开新揭示内容、领取、合法返回、重访、继续各有含义 | C-S 也不提前揭示尚需原生生成的选项；“跳过”标签不能决定业务语义 |
| 06 事件 | 当前公开选项，后续效果/新选择另形成交互 | 未知随机结果不能前置；长期结果交给 P4 |
| 07 商店 | 商品/价格/服务、购买/移除/退出，嵌套回到原流程 | 无视价格变化的旧请求必须拒绝；资料提供不代选购买 |
| 08 营火/宝箱/遗物 | 当前真实选项、效果与后续交互 | 无原生取消就不能发明；源归属不清时不猜 |
| 09 自动推进/跨幕 | 等待与 owner-ready、公开自动事件、控制交还 | 不为每次 poll 造模型步；不以新图像猜前一步因果 |
| 10 终局/退出 | 原生结果、任务结束、放弃、未知、接管分别表达 | 不把失联当死亡，不把人工完成算 Agent 全局胜利 |

SC-11/12 的记录、Agent 历史直接消费这些事实；SC-13–16 的训练、云/团队、GUI 与发行使用 P4 的独立任务/产物/管理合同，不增加另一条原生操作权威。

## 8. 六个贯穿例子及记录要求

1. **查牌后出牌。** C-L 记录真实打开/页面/返回/出牌；C-S-query 记录 Read 响应及出牌；C-S-bundle 在对应观察提供集合后直接出牌。目标轨迹只有在相应时点事实足够且省略规则成立时才可转换。
2. **奖励看过后返回。** 两次相同列表有不同 occurrence/history。Agent 可凭状态区别；原生“返回”不自动等于永久放弃。直接聚合配置也不能丢掉已揭示/已拒绝的真实历史。
3. **出牌引出弃牌堆选择。** 先选择原生完整出牌意图，出现 child 后再选牌；保持确切 parent-await，不能合成提前知道 child 内容的复合标签。
4. **信息查询过程中世界改变。** 旧结果保留来源但不能用于旧绑定提交；重新观察/绑定。在途 native outcome unknown 时不重试。
5. **中途接管。** 记录新的参与者与历史可用范围。可验证历史可提供；缺失则按显式 segment 初始化，不把本局前段自动填入模型。
6. **同场景两个 Host。** 分别声明能力并检查公开轨迹、操作、成本、随机性和恢复范围。相同 schema/种子不证明行为等价；场景设置中的私有存档不进入模型。

每个转换产生源事件引用、目标操作与观察、保留/省略/派生步骤、资格与拒绝原因。轨迹符合、实际重放、行为监督是不同结果；P4 为各用途选择，不给所有数据一个总 valid 标签。

## 9. 早期候选比较的保留范围

| 维度 | C-L | C-S-query | C-S-bundle |
| --- | --- | --- | --- |
| 原生时机/页面对应 | 较直接，仍需语义映射 | 必须证明 Read 合法条件与副作用 | 必须证明每份附带资料当时可取得 |
| 上下文 | 单页可较短，多调用 | 可按需，但历史/选择器上下文要明确 | 单步可能大，需真实尺寸测量 |
| 交互/推理次数 | 原生导航可能多 | 查询可能多，可由 Agent 固定预取 | 导航少，内部提取成本仍存在 |
| 旧 Human 转换 | 需要真实页面和操作证据 | 缺 Read 轨迹时不伪造 Human 查询 | 缺同时点事实则拒绝对应完整轨迹 |
| Host 移植 | 需实现更多原生逻辑流程 | typed public-fact 能力较易隔离，但尚需验证 | 原子多 view 一致性要求更强 |
| 记忆实验 | 真实经历多，导航差异需控制 | 获得何种信息取决于 Agent，可做匹配实验 | 某些记忆需求已由当前资料消解，不能与其他配置直接归因 |

不再从此表选择优先方案。最新版将相同 AP-Q 分别映射原生浏览和直接 Read，固定 OP-S 以避免信息与动作粒度一起变化；公平比较见新规范第 11 节。旧“policy 调用数”是假设，不是 C-L 固有成本；不同自动附带配置不能当独立协议胜负。

## 10. 当前实现复用、缺口与后续验收

复用 Connector 的绑定/复验、状态绑定 Read、请求去重与 Receipt；Native Foundation 的生命周期与 owner 观察；Host 的单实例管理；Evidence 的 typed/immutable 机制。不能直接把 Port4 的 observation-only 限制当新 Agent 通用定义。

已核查的具体风险：战斗牌堆 selector 从当前 visible holders 建目录，须补证完整逻辑集合及零选状态；NativePlayerChoiceLineage 的 parent_observed 不等于已证明 await 关系；新信息合同不由现有 complete 标签自动资格化。见 [学习与交互设计依据](../evidence/BASELINE_LEARNING_AUDIT_2026-10-06.md)。这些是 E1/P5 的实际入口，不在本轮修改代码。

P5 必查：同名对象、stale/catalog 改变、并发/重复请求、unknown 不重发；真实选择器与父续执行；资料时机与隐藏顺序；重访与重复运输；超限目录/上下文的完整拒绝；Human/Agent/gap；Host 恢复与不支持。报告每 view 的字节/token、采集/编码/推理/传输/原生等待成本，不预报未经测量的速度。

G1 需要接受：完整候选或新的有据组合、首发范围、信息能力目录、操作粒度、历史与成本口径、必需 Host 能力、超限与恢复策略、数据转换用途。P3 文档完成表示这些问题有成套可评审答案和对比，不表示它们已经被用户接受或具备运行资格。
