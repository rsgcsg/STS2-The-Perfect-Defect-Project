## 2. 六大块的解释

1. 定方向：P0–P5/G1 查需求与事实，比较完整方案，用例子、反例与测试设计确认可实施范围。
2. 收基础：P1/E0 判断现有资产如何复用，不把“清空 PR”当工程目标。
3. 搭核心：E1–E3 让环境、记录和 Agent 采用共同含义。
4. 接工具：E4–E6 贯通学习、执行、云/本地、团队和可编程入口。
5. 证实基线：G2/V1/G3 先小闭环，再完整范围，不以各组件自测代替组合。
6. 交付研究：R1/R2 发布稳定组合，再有依据地扩大实验。

## 3. 依赖、并行与唯一 owner

    P0 + P1 → P2 → P3 ↔ P4 → P5 → G1
                 P5 的检查可及早反馈 P2/P3/P4
    G1 → E0 → E1 + E2 + E3
    稳定的产物/执行契约 → E4 + E5 → E6
    最小可用 E1–E6 → G2 → V1 → G3 → R1 / R2

上图是依赖，不要求所有调查和独立实现串行。数据盘点、原生机制、接口消费者和资源约束可并行查证。共享协议、事件顺序、恢复状态机、BOM 和集成 ref 各由一个 writer 负责；其他人不能为使自己的测试通过而改变共同含义。

各 owner 先引用同一契约版本和样例。基线或接口变化时，列出受影响消费者/任务，更新验收与版本，再继续依赖工作。没有真正独立的任务时不为占满槽位而派发。

已审查增量持续进入 develop，不等待 G3 才集中合并。main 只接选定正式批次。未知外部执行先核对原 attempt，不通过新任务或删除 journal 规避。
