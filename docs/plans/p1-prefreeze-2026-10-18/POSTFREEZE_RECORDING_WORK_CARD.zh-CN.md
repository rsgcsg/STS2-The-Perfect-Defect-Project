## 1. 目标、交付与已定取舍

让用户通过已有工作台顺手开始、观察、结束录制；数据自动落盘，故障后保住已写内容，正常续玩或回退后知道数据来自哪里、可以怎样使用。交付的是可实际操作的录制闭环，沿用现有采集、派生、选样与存档 owner，不另建控制台或恢复平台。

用户已确定以下行为，实施时不再把它们列为未决项：

- 日常主按钮只有 **“开始 / 结束”**。“保存进度”改为自动落盘，并显示最近真正落盘的位置；“停止采集”放高级项。
- 自动下一局必须携带 P1 设置，列为第 1 片必修项，不能等恢复工具做完再补。
- 崩溃恢复先做轻量版，以录制顺手、保住可证明内容、说明尾部损失为目标。
- 续玩片段可采、可按实际用途使用，但不计当前完整局；不新增“跨片段完整局”资格。
- SL 原件保留，标注回退分支，默认排除自然评估；首轮训练用途到训练配置时再定。

边界：本卡不执行云上传、训练、数据删除或任意时刻存档，不把离线恢复当游戏读档，不因 Host 重放差异要求用户重录完整原件。云最小读写验证属于原冻结任务，按该任务现有授权与范围推进，不由本卡重新设门。

## 2. 一套上层链与变更类型

```text
真人 / Agent → 原生游戏与 Host → Connector 公开事实与动作见证
                                      ↓
                             Annotator 不可变原件
                                      ↓
                           校验、版本化离线 P1 派生
                                      ↓
                          选样 / 用途 / 谱系分组 → 训练或评估

GUI / CLI / API → 同一 Application 用例 → 上述既有 owner
游戏存档 → Host 原生恢复 → 新运行、录制片段 → 同一记录链
```

本卡位于三条连接：用户→应用操作、原件→数据消费者、存档→恢复运行。GUI 接线属于表示与调用调整；自动下一局携配置属于既有 P1 录制接线修复；轻量恢复和续玩关联使用既有 owner 补实现。任何新增公开字段与原件语义在开工时由其合同 owner 明确，不能让 GUI 自己解释未知、连续性或成功。完整局、自然评估和 SL 用途按第 1 节已定边界执行，不借实现暗改 P1。

| 下游需要什么 | 上游提供什么 | 接通点与最低证明 |
|---|---|---|
| GUI 能准确开始、结束与重连 | 同一 Application 用例、原命令回执与状态 | GUI/CLI/API 指向同一 session；页面重开不重启采集 |
| P1 录制绑定真实游戏与来源 | Host 的实际装载、隔离 profile 与 new/saved 来源 | 复用 prepare/attach/finish；续玩不用新局模板覆盖 progress |
| 下一局仍按所选 P1 采集 | Recorder 的连录状态与明确配置 | 首片修好下一局 Start 的 profile、origin 及相关 P1 设置传递，两局实证 |
| 派生与恢复可核验原件 | Store 的事件顺序、PB 对象、引用、落盘范围和 Close | 复用 reader/packer；恢复另产结果，原目录不改 |
| 选样知道能用到哪里 | 原始身份、逐项处置、gap/segment、父存档关系 | 接既有 decision-dataset；序列不跨缺口，分支不跨划分 |
| 续玩知道实际起点 | 原生存档、Host 加载与恢复后的真实 basis | 新片段记录 parent/save 关系；无法证明连续就明确未知 |

## 4. GUI：准备、游戏中与结束后

在既有 Workbench 录制页接同一业务用例。准备时选择新局/继续已有存档、操作者来源与“P1 完整公开信息”预设；内部 profile/schema 和旧格式放详情或高级项。显示实际游戏/Mod、隔离 profile、目录与可用空间。本机录制不要求先登录云；识别现有游戏并走受支持的绑定路径，避免重复启动。

日常主按钮只有“开始”和“结束”。开始必须先获得 owner 回执；新局在原生开局前开录，续玩先选原 profile 并开录，再原生 Continue。结束等待真实 Close，然后本机校验、封包和离线派生；不自动上传、训练、删除或退出游戏。正常终局仍沿现有 owner 自动逐局封存；若启用连录，下一局用同一明确 P1 设置开录，每局独立封包。

游戏中保留简洁小窗：录制健康、已接受/已完成/待完成/需处理数、最近记录、**最近落盘的事件位置及目录**。所有计数与落盘状态来自原 owner；不能沿用旧 canonical 子集冒充 P1 总数，不能把“已在内存记录”显示成“已落盘”。收起/关闭页面只隐藏界面，采集继续；重开读取同一 session。

“保存进度”不再是日常按钮。自动保存复用原 Store，在实测可接受开销的已完成边界更新 durable watermark；不能每次动作复制完整 prefix 或每个回调强制 fsync。轻量状态凭据确有需要时，在 Store 补窄接缝、复用不可变 PB 对象。显示真实尾部损失窗口，不承诺掉电零损失；自动落盘不等于原生游戏已存档。

“停止采集”放高级项，明确显示停采期间不会补录；重新采集产生新边界，不能推定期间没有游戏动作。玩家暂离使用游戏原生暂停，记录器保持采集；不再把采集暂停与游戏暂停混在日常按钮里。Agent 归还控制仍由 Runtime 处理。

记录详情分别展示原件/封包、派生、原生终局/退出、续玩关系与数据选择状态，例如“原件已保存，派生 1 处需处理”。提供查看原件、重新派生、定位需处理位置、选择可用数据和查看存档关系；修复保留旧失败并生成新版本结果，不用一个绿色状态概括全部资格。

## 5. 轻量恢复与失败数据利用

轻量恢复只做三件事：找出可证明的已写入范围；另建恢复产物并说明尾部缺失；用户可以继续录新的片段。先保证顺手，不做自动修复游戏、任意撤销、通用快照、自动回放补录或复杂恢复向导。优先复用原 reader、Store 和恢复报告，不要求重建完整恢复平台后才能交付 GUI。

| 故障 | 最小处理与使用边界 |
|---|---|
| GUI 关闭、刷新或断线 | Recorder 继续；重连查询原 session 和原回执，不创建第二份录制，不盲目重发未确认操作 |
| 原件完整，转换器漏映射或有 bug | 保留原件和旧 FAIL；修原 adapter 后生成新派生、版本和影响报告，无需重录 |
| 动作结果 unknown 或 pending | 查原生命周期/回执；无法确认就保留原状态，隔离本项及依赖范围，绝不重打游戏动作来造结果 |
| 未提交拖牌或明确原生取消 | 保存真实上下文和取消处置，0 成功标签；专门批准的解释不扩成一般 unknown 豁免 |
| 缺 Reads、缺 blob、局部坏行或缺口 | 标出精确影响范围，保留独立完整决策/段；身份或顺序整体无法证明时阻断对应整体，不从后态补造当时事实 |
| 崩溃、JSON 尾部截断、Close 失败 | 确认原进程不再持有目录，保留原目录/字节；另产可验证前缀或恢复包，标 partial/缺失/unknown，不伪装正常 Close |
| 磁盘满或写入失败 | 立即显示采集不健康和最近成功落盘位置，提示暂停推进处理空间；不强退游戏，不继续显示正常，也不补造故障期间动作 |
| pack、派生或传输失败 | 已落盘原件继续保留；按同一输入身份重做可重复数据任务并保留失败 attempt，不能等同于重发游戏动作 |
| Managed 与 Reference 不同 | 保留 Human 原件与首个真实分叉，修相应 owner；不删差异、不跳严格比较、不把整局录制自动作废 |

数据保留三层：原件、某一版本派生、某一用途固定选择集。选择集记录入选/排除 ID、原因、版本与原顺序，坏项不从原件删除。单步模仿按 Input/Target 所需证据判断；状态转移需要真实执行和正确后继；历史序列在 gap 处断开，memory 重建/reset 由 InputSpec 声明；回报与胜负必须关联本分支真实终局，不能用后来赢的分支改写先前失败。

完整局继续沿现有严格定义。片段有用不等于完整局通过，入库不等于可直接训练，选择条数不等于学习效果。恢复报告与选择报告保留原故障、排除分母及范围，避免只展示成功部分。

## 6. 原生存档、续玩与 SL 归属

游戏存档保存原生可序列化状态，录制原件保存已经发生的过程，训练 checkpoint 保存训练状态，三者不能相互替代。正常保存退出后 Continue 可以属于同一游戏谱系，但产生新的 runtime 与录制片段；当前续玩片段可采可用，**不计完整局**。若实际恢复到已经经历的更早状态，就登记为回退分支；崩溃恢复不推定玩家故意 SL，但真实回退照记。

SL 原件与各次尝试保留，默认排除自然评估。父 save、重复经历及共享前缀有关联的片段留在同一 train/dev/test 组，公共前缀不因 SL 或重新封包重复计数；各次真实决策 occurrence 保留。SL 是否用于首训、以何种监督和权重使用，到训练配置时由研究 owner 按用户决定落实。本卡不先替训练配置选择用途。同 seed 新开局仍是新局，seed 不能证明同一次运行。

最小关联证据包括父片段/事件位置、save 内容身份与字节数、游戏/Mod/候选、profile 代次、native new/saved 来源、新 runtime，以及恢复后的真实初始边界。公开状态相似、楼层或 HP 相同不能证明连续；无法确定父 save 或回退关系就显示未知，不硬拼。

正常退出沿原生受支持的 Save & Quit：等待已提交动作完成→确认录制自动落盘位置→原生保存退出→确认稳定 save 的身份与边界→Close/pack。不能许诺战斗任意时刻保存；不能证明 save 覆盖当前画面时，显示已有存档位置与不确定性。重进使用原 profile，先开录再 Continue，记录实际起点；禁止套新局 baseline 覆盖 progress。

| 对象与 owner | 本批责任 |
|---|---|
| STS2 存档与 Host profile | 使用原生保存/继续，工作副本和归档快照分开，不改 save JSON 骗加载 |
| Annotator 原件与 Store | 保事件、引用、落盘范围、Close 与恢复产物；不重建旧 BoundAction 或进程内对象 |
| Application / Workbench | 编排命令、回执、数据作业与展示；页面重连不叫游戏读档 |
| Runtime / Agent | 保留消费与动作证据；进程死亡后从受支持 save 开新片段，历史/memory 显式重建或 reset |
| Evidence / Curation / STPD | 验证、不可变派生与用途选择；不因传输核验通过授予训练或自然评估资格 |

Reference 原生续玩优先。Managed 已有地图边界 save/load 保留其限制，跨 Host 同存档对照另做窄实验；任意时刻恢复、跨 Host 通用互读、云存档冲突合并不属于本批。

## 8. 开工与交付方法

负责人开工前只做一次必要刷新：当前分支/候选/未提交改动、现有 agent 与游戏/录制进程、冻结完成状态及本片实际授权。确认范围后走原 owner 实现，补真实边界、可选字段和状态的必要测试，稳定候选做一次相称复核；不对每个按钮更名跑全库或整局。发现需改变 P1 能力、完整局或研究用途时返回用户，不靠字段屏蔽或 fallback 吞掉矛盾。

每片交付记录具体可用行为、源码/包/实际装载身份、最短真实操作结果、失败原件与未验证边界。源码测试、安装、现场采集、完整局、双 Host 严格等价与训练效果分开报告。该片达标则关闭，不等待后续能力完美；下一片仍按冻结后队列安排，不能从本卡的存在推断已经获准部署或重装。
