# 环境与场景管理：独立于模型的 1a 交付

日期：2026-09-29。用户方向与实施边界；不是新 wire/schema，也不是运行资格声明。
源码核对起点：`46e6adba871dc193062ecaaa58b0a04d2ddf0ca8`。

## 要交付什么

环境把一个具体 STS2 Host 变成可由人或模型使用的、忠于原生的文字游戏，同时提供
独立的实例和场景管理。最终目标是最强 STS2 AI；稳定环境让错误能被复现、不同模型
能公平比较、训练能扩展，而不是把环境规则和某个模型写死在一起。

```text
真实游戏 / Managed Host / 以后验证过的其他 Host
  → 各自原生适配器 → Connector 公共文字游戏接口
                        → 人类文字客户端
                        → Policy Runtime → 模型适配器
                        → 合同测试与评估驱动

工作台 / 测试工具 → Host Runtime 管理实例、配置和恢复
                 → 场景资料与评估应用（复用现有产物存储）
```

两条入口共享精确身份，但权限和用途不同。Host 的连接入口由 Host Runtime 拥有，
不为此增加第二套游戏规则、第二份成员数据库或大规模调度框架。

## 同一实例的生命周期与连接

2026-10-01 的源码核对发现：原工作台直接持有 Managed JSONL 子进程；模型若另外
启动一个 driver，就会另开一局，共用原 stdin 则会竞争回复。因此下一交付采用
**一份 Host 服务持有一局游戏，工作台与 Policy Runtime 分别作为客户端**。
这是一条现有会话的本机连接入口，不是团队调度中心。此处是实现约束；只有对应源码、
包与运行检查完成后才能称已接通，不能据本段文字升级当前安装资格。

```text
工作台：启动 / 场景 / 管理恢复 / 关闭 ───→ Host Runtime
工作台：文字人工操作 ────────────────→ 同一 Host 实例
Policy Runtime：模型操作 / 释放控制 ──→ 同一 Host 实例
                                         ↓
               Managed 原生适配器（遵守 Connector 公共文字快照/动作合同）
```

- Host 进程独占原生子进程和原有命令序列；客户端不再各建一局，也不增加第二个 stdin
  消费者或第二条游戏命令队列。模型仍不拥有场景启动、存档或游戏规则。
- 模型 Human/Stop 释放其控制权；网络断开本身不等于确认释放，也不关闭整局。只有
  明确的环境关闭结束 Host。进程失联、原生结果未知、释放失败分别保留真实状态。
- 重新开局或管理恢复必须针对调用者实际看到的实例和游戏连续性；延迟的旧接管、
  重开或动作请求不能作用于新局。恢复控制经过原有执行队列和真实释放应答，不能
  清空 taint 假装成功；不能恢复的实例先保留结果，再显式关闭重开。
- 工作台状态轮询读取不改变菜单的状态入口。旁观者不能因重新投影文字页而让模型
  当前快照失效。公开状态与私有控制凭据分开，模型输入和运行报告均不包含凭据。
- 模型声明其输入、输出和游戏支持要求；精确 Host 包与原生构建由环境配置绑定。
  运行记录同时保留要求、实际绑定与实例事实。同一权重换 Host 仍需新绑定和兼容
  核对，不能把原生 Mod 身份伪装成 Managed 身份，也不必仅为更换运行位置重新训练。

先支持一台本机上的一个明确实例，保留旧 JSONL 工具和原生桌面连接路径。远端位置
需另行提供权限、网络与资源边界；本机 loopback 服务不自动成为已部署团队 worker。

## 记录与结果关联

环境、文字人工操作和模型运行共享实例及游戏连续性身份，记录仍由各自现有 owner
维护。工作台人工报告只证明它确实观察并提交的那部分操作；模型的决策、控制交还和
结果由 Runtime Agent-run Evidence 保存。原游戏鼠标／手柄的 Human 见证仍由
Annotator 捕获，不能因调用的是同一环境就混成 Human 数据。

工作台可以把同一实例的这些结果放在一个运行详情里，但不能将缺失区间、重连或
其他客户端操作补写成完整轨迹。公共快照序号能帮助关联，不能单独证明因果后继或
每条操作均已记录。场景和已封存结果继续引用现有不可变产物，不再复制一份 Host
轨迹数据库。关闭工作台窗口、停止模型、关闭环境和封存各自报告必须分别显示结果。

新工作台报告以 `workbench-segment-v2-host-owned-service` 标记客户端操作片段：
“结束本段操作”封存工作台实际参与的部分并脱离连接，不能写成 Host 已关闭。
同一 Host 可在模型运行结束后重新连接；报告保留同一游戏连续性和前一片段关联，
不把中间模型操作补成工作台人工操作。旧报告没有该标记，保留原先由工作台拥有
子进程的结束语义；新旧报告不混用关闭判据或用于同一独立开局比较。
两个新开局可复用同一 Host 服务，但必须具有不同的游戏连续性身份；不能仅凭
两个报告 ID 或两次浏览器连接声称存在两个独立游戏。

## 游戏内接口与管理接口

| 能力 | 事实与操作 owner | 使用者与边界 |
|---|---|---|
| 当前原生逻辑页、公开状态、完整 A(S)、信息页 | Connector 消费 Native Foundation/Host 原生事实 | 模型、人类文字客户端、评估；不包含未访问页或隐藏 RNG |
| 选择、目标、返回/取消、确认、结束回合等 | Connector 绑定并执行前复核，游戏最终执行 | 每次请求绑定当前实例/快照/动作；unknown 不自动重试 |
| 原生鼠标/手柄见证 | Annotator 消费共享语义与真实生命周期 | 不强行把人的原生输入改成程序命令，不冒充 Agent 为 Human |
| 实例发现、启动/停止、隔离目录、健康/版本 | Host Runtime | 工作台、管理员、批处理工具；不进入模型动作菜单 |
| 种子开局、存档导入/保存/恢复、复制场景 | STS2 拥有 RNG、原生存档格式/内容和恢复语义；Host 代理受支持请求并管理隔离与身份 | 有权限的场景准备和评估；不能在正常局中给模型回档或窥视 |
| 场景名称、标签、来源、产物、实验结果关系 | 项目应用与现有 ArtifactStore | 一份不可变场景产物、多份独立运行；目录索引可重建 |
| 测试种子列表、训练/评估隔离、奖励、指标 | STPD 研究/评估 | 环境不决定模型输赢指标、数据用途或 Gold 准入 |

文字页面 S 包括当前公开原生内容和明确的文字操作位置；系统内导航可以只改变文字
位置，但真实游戏状态变化必须体现在后续观察。是否存在某动作按原生与当前接口核对，
不为减少算力静默删候选。环境适配不读取 STPD 模型参数、记忆或训练标签。

## 种子、存档和分路不是同一种恢复

1. **种子开新局**：固定游戏版本、内容/Mod、角色/难度与实际种子。相同种子不是任意
   中间状态，也不保证不同版本或不同动作顺序的运行结果相同。
2. **原生存档恢复**：保存引擎实际支持的边界，注明恢复到当前页、房间入口或其他
   原生位置。复制原件到隔离实例；不覆盖用户正在玩的存档，不宣称字节复制等于决策点恢复。
3. **起点加重放**：从明确起点复放已确认动作，逐步核对状态/候选；遇到漂移、拒绝或
   unknown 停止，不跳过差异。耗时算进恢复成本。
4. **精确决策点检查点**：只有引擎能保存 RNG、未完成选择器/延续和必要运行状态且
   恢复测试通过时才提供。当前不能仅凭 `save`/`load` 命令名声明它存在。

从同一起点分路，先用多个隔离 worker 加载同一个不可变起点，各自执行自己的动作，
输出分支来源和结果。只有上述精确恢复与吞吐合格后，才把它当成 MCTS 的快照能力。
场景库在 1a 可先支持种子/实际存档/受控 setup；任意战斗状态克隆不是暗含承诺。

## 简单的日常流程

工作台一个“环境与场景”入口：选择执行主机和兼容环境 → 选择“新局”或已保存场景 →
启动一个隔离实例 → 选择人工文字操作、模型或重复测试 → 查看结果、保存可恢复起点。
高级处显示实际来源、seed、恢复级别和版本；普通用户不用拼路径或 shell 命令。

“用同一场景比较模型”引用同一场景 ID 和固定评估协议；修改卡组/角色/敌人等 setup
产生新场景，不悄悄改旧起点。批量只设置数量/资源上限和已支持恢复方式，先显式选择
CPU/GPU/Host，避免先建设通用集群调度。团队登录增加授权资源，本机流程不依赖登录。

保存和运行记录至少能追到：Host/游戏/适配器版本、内容与 Mod、起点产物摘要、恢复
边界、实际种子及可用 RNG 资格、setup 来源、父场景/分支、运行终态。这里是需要表达
的事实，不预先冻结新 JSON 字段；具体实现优先复用已有 manifest/profile/receipt。
完整存档、隐藏状态和私有路径留在受控存储，公共页面与模型输入不泄露它们。

## 当前实现依据与缺口

2026-09-30 的首个场景库切片保存 Defect A0 固定种子开局配置：名称、Host 合法 seed
（默认 `M2H0ST20260929A`）、文字输入格式、Host 包 pin 与精确 Managed 构建身份，
产物不可变。seed 按当前精确 Host 客户端规范化并校验。工作台显式保存后，可从该产物
启动新的独立 Managed 进程；启动仍逐项复核当前配置、安装包、候选构建与引擎返回的
实际种子，并核对公开首屏中的 Defect/A0。已封存的运行报告额外保留本次实例最初观察的
文字页和 seed 身份。显式比较两份报告时，必须同属保存起点、各自确认关闭、实例 ID
不同、开局菜单完整且没有未知错误，才显示“已核对固定种子独立开局”。比较只展示
种子、构建、输入格式、首屏候选数、动作数及结束状态；不证明轨迹或模型水平一致。
旧报告缺少初始页或场景关联时不能获得此结论。当前切片不是原生存档、任意中途状态
恢复或 MCTS 检查点。

- `components/host-runtime/README.md`、`src/profile-isolation.mjs`、
  `src/profile-template.mjs`：现有生命周期、实例隔离、模板工具，不等于统一场景库已完成。
- `experiments/managed-exact/manifest.json`、对应 README 和固定 patch：Managed 候选
  复用本机合法游戏文件；`.NET`、游戏/平台 tuple 和原生 shims 仍是实际依赖。
- `src/managed-player-environment.mjs`：已有 Player Environment 投影与绑定；必须另外
  核对当前 text-menu 公共合同，不能因旧 PE 通就说当前文字接口全通。
- `src/managed-recovery-probe.mjs`、`src/managed-native-binding-gates.mjs`：已有恢复与
  绑定检查入口；所测对象、游戏和范围由具体回执决定，不借旧结果覆盖新包。
- `docs/plans/TEXT_STS2_IN_RUN.md`、Connector 公共合同与 SDK：当前文字语义的 owner；
  Managed 适配复用合同，不能为 CLI 便利降级成旧全局状态或隐藏信息集合。
- `python/stpd` 数据/评估与 `python/spireagent` 产物/应用：复用存储与报告，不能让
  Host 组件导入它们的策略、奖励或研究用途代码。

## 独立验收

环境正确性用模型无关的确定性客户端测试：合法动作/完整绑定、不可用/过期/取消/
unknown、nested selector、跨场景续接、终局、实例隔离和恢复。真实游戏与 Managed
分别报告可表达、合成通过、当前包可运行、原生已验证、尚未知，不宣称全平台等价。

跨 Host 的差异比较以同一原生机制和公开事实为单位；不同 opaque ID 或表现层顺序
不是规则差异。种子相同而动作/RNG/版本不同不作为“模拟器错误”的充分证据。
性能报告分环境推进、序列化/传输、模型推理、记录与恢复成本，实测候选数/页长/并发；
不拿 raw CLI 吞吐冒充 Connector 或完整训练吞吐。

环境管理子系统的最小可用切片：Managed 当前文字合同有明确已测范围与缺口；至少
一类已验证可重复场景贯通保存/恢复/独立重复运行/结果比较；两条入口及权限不混淆；
日常入口可用。这个切片不替代整体 1a 的全目标场景连接矩阵、跨场景/整局系统基线
和产品门槛；未测场景仍列为待完成。更高级的精确克隆、任意改局、MCTS 和自动集群调度按
实测需求后续推进，不为了凑“全功能”做未经验证的承诺。
