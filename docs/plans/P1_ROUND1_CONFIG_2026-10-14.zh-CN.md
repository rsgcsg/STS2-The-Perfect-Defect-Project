## 0. 一句话

用全部人类录制，在 P1 v1 观察上做行为克隆，训练两个模型：R1-A（现有 Structured M2 原样，作对照）和 R1-B（加当前局面摘要、8 槽记忆、卡牌 ID 嵌入）。
训练步数超过 1000，按规则在远端 GPU 上跑；本机只做 ≤ 1000 步的冒烟和过拟合检查。

## 1. Agent 怎么接协议

### 1.1 每一步发生什么

```text
Host 到达稳定决策点（完整目录、不在结算）
 → P1 v1 适配器取：snapshot-1（当前页 + 常驻信息 + 动作目录）
                    + 当前声明的全部 Reads（run_deck、combat_piles、shop_catalog，同一快照内）
 → 组装成一个资料包，校验同一快照、完整、未过期
 → Agent 程序：资料包 → 结构化树 → 模型（编码 → 打分 → 写记忆）→ 在完整目录上取最高分
 → 适配器下发所选动作 → 回执 delivered / not_delivered / unknown
 → delivered：等下一个稳定决策点；not_delivered（过期）：重新取资料包，Agent 重新选，记忆不前进；unknown：本局删失结束
```

### 1.2 两种 Host 上的具体路径

| | Reference（真实游戏） | Managed（训练、评测） |
| --- | --- | --- |
| 取资料包 | Policy Runtime 的有状态 Read 端口（冻结 WIP 里的 `public-observation-stateful-read-v1`）：取全部已声明 Read，单个 ≤ 1 MiB，最多 8 个，合计 ≤ 8 MiB，30 秒期限 | 评测/训练驱动（任务 D）在进程内调 Managed 的 snapshot 与 Read，组装成同样格式 |
| Agent 进程 | 独立进程，经 NDJSON 端口（Decision4 有状态版本 + Read）收资料包、回分数和选择 | 同一份 Agent 代码，在驱动进程内直接调用 |
| 缺 Read | 在线时缺一个已声明 Read：整个资料包作废，不更新记忆，重新取 | 同左 |
| 现状 | Read 端口在冻结 WIP 和候选 8d593a34 里，未集成 [待核] | 驱动待建（任务 D） |

### 1.3 不进模型的东西

快照 ID、动作绑定 ID、请求 ID、时间戳、回执、Agent 自己以前的动作（I/F 关闭）、任何程序推导的计数或提示。

## 2. Agent 内部

### 2.1 组件

| 组件 | 做什么 | 来源 |
| --- | --- | --- |
| 输入投影 | 资料包 → 结构化树：四个根（常驻信息、当前页、状态、Reads）；对象成为实体节点，字段成为子节点；有公开顺序的数组保序，其余当无序袋；牌组和牌堆当多重集保留重复 | 冻结 WIP `public_structured_inputs.py` + `public_structured_spec.py` |
| 模型 | 编码、记忆、打分（第 3 节） | R1-A：现有 `structured_m2.py`；R1-B：新模块 |
| 选择 | 评测时取全目录最高分；不过滤、不改目录 | 现有 |
| 记忆管理 | 每局开始 W 清零；每个新的合格决策点前进一次；同一决策点重读不前进；录制中有缺口时切段并清零 | 现有规则 |

### 2.2 输入上限

单字段 ≤ 4096 字节，总文本 ≤ 1 MiB，≤ 65,536 节点，≤ 262,144 条边，≤ 16,384 个候选，资料包 ≤ 8 MiB。超限直接拒绝，不截断。

## 3. 模型

### 3.1 R1-A：现有 Structured M2，不改结构

| 部分 | 配置 |
| --- | --- |
| 文本编码 | UTF-8 字节嵌入 258×32 → Conv1d 32→64（核 3）→ GELU → 掩码平均 → 线性 64→96 |
| 节点 | 字段名编码 + 字段值编码 + 9 类节点类型嵌入 + 3 维数值特征（已知、有界值、signed-log1p）→ LayerNorm |
| 关系 | 实体内字段聚合；1 层稀疏关系传播（父、子、引用、被引用 4 类） |
| 记忆 W | 1 槽 × 96；查询读 [旧 W；当前实体] 形成提议，sigmoid 门逐维混合 |
| 打分 | 候选 = kind/verb/label 文本 + 角色指向的当前实体；读 W；MLP 192→96→1 |
| 顺序 | 编码 → 写 W → 用新 W 打分 |
| 参数 | 180,545 |

### 3.2 R1-B：主模型

| 部分 | 配置 | 为什么 |
| --- | --- | --- |
| 宽度 | 128 | 数据只有约 2 万条决策，不宜更大 |
| 文本编码 | 同 R1-A，输出 128 | 新卡、新文字仍能理解 |
| ID 嵌入 | 卡牌、遗物、药水、能力、怪物的 definition_id 哈希到 4096 桶 × 128，加到该实体节点上 | 直接记住"这张卡是什么"，省数据 |
| 关系 | 2 层 | 让卡牌和它的升级、目标、所在牌堆之间的关系多传一步 |
| 当前摘要 G | 4 个可学习查询对全部当前节点做注意力 → 4×128，每步重算，不跨步 | 当前局面直接给打分器，不必挤进记忆 |
| 记忆 W | 8 槽 × 128；写入时各槽查询读 [旧 W；G；当前实体]，门控混合 | 让不同信息存在不同槽 |
| 打分 | 基础分 s0 = MLP([候选；对 G 与引用实体的注意力])；记忆修正 Δs = MLP([候选；按候选读 W])；门 g = σ(·)；s = s0 + g·Δs | 当前判断和历史修正分开，可单独关掉记忆做对照 |
| 顺序 | 用旧 W 和当前 G 打分 → 再用当前观察写 W | 记忆只承载过去 |
| 价值头 | MLP([G 平均；W 平均]) → 预测本局最终层数（归一化回归）和是否获胜（logit） | 给第二轮强化学习的 critic 热启动 |
| 参数 | 约 90 万，其中约 52 万是 ID 嵌入表（实现后报告实际值） | |

结构来自 2026-10 的 M2 增长提案（G4/K8 方案），原文在 2026-10-13 交接包 `discussion/m2-architecture-and-growth-proposal.zh-CN.md`。

## 5. 损失

每个训练块（一段里连续 32 个决策点）：

```text
L = 平均_{块内有效标签} CE(softmax(全目录分数), 人类选择)
  + 0.1 × [ MSE(预测层数, 实际层数/最大层数) + BCE(预测胜负, 实际胜负) ]   ← 仅 R1-B，仅有终局记录的局
```

不做标签平滑，不采样负例，不缩小目录。没有标签的决策点只前进记忆，不产生损失。

## 7. 计算与预算

| 项 | 内容 |
| --- | --- |
| 规则 | 超过 1000 步的训练默认在远端 GPU；本机 CPU 只做 ≤ 1000 步的冒烟和过拟合检查 |
| 本机检查 | 每个模型先在 64 条决策上过拟合 300 步，确认损失能降到接近 0、无 NaN |
| 远端 | 复用历史上 d6 M0 用过的 Modal 路径和现有远端训练候选（A/B/C）；单卡 A10G 级别即可 |
| 必须先做的工程 | 训练引擎目前只支持 CPU、单序列；需要加批量段训练和 GPU 设备支持（新增任务，见计划） |
| 时间与费用 | 每次运行预计 1–2 小时，4 次运行（R1-A ×1、R1-B ×3）约 USD 5–10，在本轮 USD 20 额度内 [冒烟后按实测更新] |

## 8. 评测与验收

1. 开发集：负对数似然、top-1 准确率，分页面类型、分角色；Defect 单独列。
2. Managed：`smoke-20`、`dev-500`，对比随机策略和 d6 M0。
3. 真实游戏：最好的一个模型跑 `ref-20`。
4. 记忆对照：R1-B 关掉记忆修正（g = 0）再评一次，看记忆有没有用。
5. 结果进 SCOREBOARD。预期：第一轮到 L1–L2。

## 9. 风险和待核事实

- 训练数据来自真实游戏的 Reference 录制，评测在 Managed 上：如果 Managed 的观察缺字段，会出现训练和评测输入不一致。任务 E 必须先确认。
- 冻结 WIP 的 Read 种类不含 `surface_card`；卡牌详情是否已在快照里，需要核实。
- 15,290 的含义、带 Reads 的比例、有终局记录的局数，都会改变第 4 节。
- 批量训练和 GPU 支持还不存在，是第一轮的关键路径。
