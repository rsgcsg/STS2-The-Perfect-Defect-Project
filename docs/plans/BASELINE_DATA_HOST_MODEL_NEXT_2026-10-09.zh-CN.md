## 2. 数据怎样进入训练

沿用现有链路：原始不可变记录 → 严格 Evidence 验证和 Receiver →
ArtifactStore 与来源目录 → 权限、用途和历史 use/Gold →
配方指定的投影、目标和划分 → 训练 input/run/attempt →
checkpoint/model → 导出、登记、加载与评估。
模型配置、训练配置和数据配置可以属于一个完整配方；只在复用、兼容或审计确有必要时
分别版本化引用，不先建多套相似的 registry。

原始 bundle content ID、实际 archive hash、研究 manifest artifact ID 都保留。
副本迁移或重新投影不重置历史曝光，也不解除 Gold。目录和可重建索引可以重建，
use/Gold/权限账本不能按缓存处理，回退代码不能覆盖较新账本。

现有 6,398 条实际选择与分支事实可以支持明确的 legacy 配方；
它们不自动满足新 native 模型完整历史与目标合同。
其中 5,522 条关联原生 defeat，876 条终局未知；前者不是 5,522 个独立终局，
也不是任意 horizon 的合格 O 标签。对这 14 源组成的集合执行严格 FullRun 准入时
返回 `unresolved_or_unpersisted_occurrence`；这不是逐源各自拒绝的结论。
局部样本可用与完整 run 可用分别判定。

新 Source V2 首先打通实际公开观察与输入的记录、验证和研究转换。
N 只取合格的实际选择；无动作观察可推进记忆但不伪造动作标签。
Z 需要选中分支的因果/后继证据，不能拿下一条观察或投递成功充当 Commit。
O 固定指标、单位、终点与删失规则，并记录实际后续策略。
未来标签与当前模型输入分开。AI 操作保留 Agent 来源；UI seam 也不机器证明操作者是人。

采集顺序是少量真实片段 → 全链验证 → 扩大采集 → 小批训练测量 →
约万条合格交互尝试及必要比较。若需要真人新增数据，应先给出确切场景和录制方式，
避免在协议尚不可靠时要求大量重录。数据不足如实保留，不补造历史或标签凑数量。

## 3. Host 与存档的安排

官方有窗口 Live 与官方 headless Reference 都运行游戏原生程序；
Managed 是独立的精确游戏程序集加适配层候选，须单独验证。
当前没有证据证明通用云端游戏 Host 已部署。训练 worker 不等于游戏环境。

优先复用原生安全边界的保存、继续、不可变备份、隔离副本与恢复管理，
再对现有 Managed 做同场景真实性和吞吐测量。只有实际瓶颈值得投入时，
再考虑 Hybrid 或独立模拟器。独立模拟器拥有明确实验语义，不冒充原生规则权威。

profile 模板、原生 run 存档、模型 W、训练 checkpoint 是四种不同对象。
原生保存函数会捕获部分错误，Task 完成不足以证明保存成功；需核原生结果与实际字节。
原生 Continue 会更新 reload 计数，因此保留不可变备份并加载工作副本。
恢复后重新建立运行时和动作绑定；W 只在模型身份与已消费前缀精确匹配时恢复，
否则明确冷启动。保存/回档属于管理侧，不授予策略任意重开能力。

“每步记录”“从合法原生存档继续”“任意时刻完整还原内存”分别验收。
当前历史记录只支持限定地图保存/加载和有限跨 Host 对照，不能推出战斗中随时回档。
实时切片恢复是可选研究方向；其规则/RNG/异步任务/UI状态、成本与复现能力需要单独评估。

性能先测有效完整决策、完整局、启动/重置/清理、CPU/RAM、推理时间及失败率。
旧硬件和旧产物的吞吐不能相除作当前加速比。训练若主要耗在模型编码，
先重写游戏模拟器也未必能降低端到端成本。

## 4. 模型与训练扩展

保留文本 LightAction M2 作为独立参考。先稳定结构 K1/carry/N/TBPTT4，
再用相同合格数据做 K1/K8 与 carry/reset 配对、一个有意义的 backbone 对照，
以及有目标资格的 N/Z/O 有界比较。它们仍是既定义务；不自动展开历史所有实验组合。
文本与结构同时改变了表示和计算图时，明确称系统比较，不能称只改了一项。

当前 TBPTT4 保留 W 的数值历史，但梯度在块边界截断；不是四步失忆。
延长窗口、全段反传、重计算省内存、只在终点计算 loss、改变压缩状态是不同方案。
全段梯度需要同一参数版本的连续展开；已 detach 的 checkpoint 不能恢复旧计算图。
先依据短段测量再决定窗口、宽度、多槽、层数或分层记忆，不同时改全部轴。

RL 和生成式模型按实际研究问题追加：需要明确 reward/terminal/truncation、
行为来源、数据覆盖及环境资格。生成结果最终仍通过 Connector 的完整操作关系解析，
不能构造原生 operands。配方注册只代表代码支持，既不代表权重已训练，也不代表实机已通过。

成本用同配方的小规模实测估算，包括准备/编码、训练、评估、保存、失败及传输。
本地无供应商费用也记录时间和资源。GPU 仅在总时间和预算有明确收益时启用；
累计付费上限仍为 USD20，不是每个变体各 USD20。未取得当前报价前不承诺 GPU 小时或金额。

## 5. 当前执行顺序与非承诺

当前优先完成原生信息/操作遗漏、Source V2、已审查子包的组合与真实 Agent 小范围运行；
并行整理已有资产和配方，不把可选模拟器、全程反传或全部模型变体变成新前置。
源码通过、已安装、实际运行、真实数据准入、训练完成和模型质量逐级报告。

后续排期以门禁为准：实机小范围 Agent 依赖组合/原生操作可用；较大训练依赖数据闭环
和小批成本测量；自然完整局依赖机制覆盖与稳定控制；通关能力依赖真实评估。
当前不据源码完成比例承诺日历日期、胜率或整个 G2/V1 已完成。
兼容性删除属于另行说明并审批的工程取舍；本方案没有删除已有必要兼容。
