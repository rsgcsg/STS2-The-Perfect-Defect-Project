# Managed P1 equivalence and use boundary

Managed is an engineering Host with exact game/candidate/package identities. It
can stand in for Reference only within the actual paired states and fields that
passed the complete P1 comparison. A scene name, shared game DLL, successful
process exit or natural loss does not qualify every mechanism in that scene.
Reference and Managed evaluation populations remain separate until the user
approves a pooling policy supported by the exact evidence.

The game assembly owns rules, RNG and effects, but Managed runs it in TestMode
outside the shipped SceneTree. The exact candidate manifest's `semantic_shims`
identify wait, UI, selection, reward and asynchronous task adaptations. These
seams need differential evidence; sharing an unmodified `sts2.dll` alone is not
proof of execution, presentation or P1 equivalence.

## Settled logic, native rules and replaceable Host implementation

The user approved this design on 2026-10-27: P1 observes public logical facts at
a decision boundary after preceding effects have settled, rather than an
animation frame. A child selection is a real boundary even while its parent
effect awaits that input. The exact field/version policy belongs to
[P1_GLOBAL_R1](../../../docs/protocols/P1_GLOBAL_R1.zh-CN.md); the general principle
does not silently change existing counter values, comparison rules or originals.

| Rule | Managed responsibility |
|---|---|
| M-1 | The original game assembly owns rules, RNG, effect results and legality. Do not implement a second rules engine. |
| M-2 | Host clock, animation, waits, UI/SceneTree, scheduling, processes and recovery may be replaced substantially when the same P1 logical result is preserved. |
| M-3 | Align settled public logic, not native presentation timing. Distinguish a wrong game result from a transient display value before choosing the owner to repair. |
| M-4 | Normal clock and the shipped game are diagnostic controls only. Slowing Managed is not the repair or default. A rule truly dependent on real time requires an explicit user decision. |
| M-5 | Register each replaced native seam, unchanged rule/result rationale, differential evidence and regression in the existing candidate manifest `semantic_shims`; do not create a second registry. |
| M-6 | Locate the actual blocked or faulted native operation. Complete its logical work through the registered Host adaptation; waiting longer or retrying an unknown is not a repair. |
| M-7 | The replaceable implementation promises native rules/RNG and qualified P1 equivalence, not native animation or wall-clock timing. A future Host must pass the same declared interface checks. |
| M-8 | Concrete P1 meaning/comparison changes need an explicit new version and user-approved field list. Keep old raw/projections immutable and state exactly which old sources can be reprojected. Internal repairs preserving M-1 and public results follow the task's standing engineering authorization. |

For a timing-dependent field first use its separate native logical value in both
Hosts. If that value is itself delayed behind presentation, only an explicitly
versioned, mechanism-specific function of the **same snapshot's public facts**
may supply the settled value. Never splice later frames or expose private total
counters. If neither route is justified, retain a field-level unresolved
difference for the user. `LASTING_CANDY`'s historical display exception remains
limited to its original approved conditions; it is not a general counter rewrite.

The M2a investigation found a concrete M051 counterexample: the original
Phantasmal Gardener enemy move calls missing `Godot.Mathf.Log(float)`, so its
native turn task faults before the next play boundary. Its Host stub must match
the shipped Godot `MathF.Log` implementation. This is a missing dependency
method, not evidence that the combat needs a slower clock. Source/native fixture
and full-seed runtime confirmation remain separate evidence levels.

## Compare the actual interface, then the consumer

For each interface retain the compared denominator, complete-public matching
count, full Result matching count, frozen model input/score matching count and
exception IDs. Compare the whole observation, finite catalog, chosen action and
Result under one public entity/action bijection. Keep text, duplicate instances,
selected/effect/display order and all undeclared extension fields. A graph work
limit or unsupported shape is incomparable, never equal. Approved exceptions
still remain differences and narrow a claim instead of increasing its numerator.

P1 r1.6 is explicitly selected at the SDK/API boundary. It adds unordered
membership-ID sets while retaining selected-card order and displayed lists.
The normal live r1.5 Runtime handshake, recording combination and frozen model
package do not silently upgrade. `tools/p1-order-derive.mjs` produces an
order-only trajectory view with source/per-observation hashes, including native
presentation witnesses; it changes only revision metadata. The ordinary native
replay CLI still verifies its original r1.5 derivation. A r1.6 view is consumed
through the explicit SDK/replay API and its own receipt, not passed off as the
original Agent's input.

P1 graph equality does not imply equality of a frozen order-sensitive model.
The 2026-10-26 analysis of three retained F2 pairs found 268 graph-equivalent
model points: zero identical model Frames, 13 identical probability vectors,
and 267 identical greedy choices. One point changed from Defend to Strike.
This was new paired shadow inference with the original checkpoint-438 package,
not the original live Agent's probability record or a new Host qualification.
Probabilities are a full-catalog softmax of the actual model logits; the normal
Agent returns logits and chooses their argmax. Align actions using the successful
complete graph's bijection; never guess a mapping from kind/label alone.

borrow the historical Host40 serial/parallel 40-run result for a newer candidate.

## Existing measurement and operation

`ManagedEpisodeExecutor` records disjoint monotonic `phase_seconds` for prepare
(Host/reset/identity/registration), execute (Runtime/Agent loop and its original
Stop/process finish), finish (typed verification/outcome/metrics), preserve
(publication/copy/full typed peer readback), and close (Host close plus actual
exit). A failed phase retains its elapsed time; unvisited phases are absent.
Execute is not pure inference; preserve is not pure network time. This measures
the existing lifecycle without skipping preservation or reusing world state.

The normal evaluation path remains the application's durable ledger and
`spireagent.workbench.reference_suite.run_suite` with a Managed executor.
`stpd/evaluation/managed_suite.py` still serves the explicit
`python/tools/evaluate_managed_suite.py` uniform-complete-bound-catalog engineering
CLI and its hash-bound outcome verifier/tests. It consumes snapshot-1 with a
uniform strategy, not the frozen P1 model evaluation path. Its continued callers
are a reason to preserve that separate purpose, not a second route for scoring
checkpoint 438. This work only inventories it; no routing was rewritten.

Model registration binds one immutable package to the exact negotiated Host,
Runtime, environment, adapter and input contract. Separate registrations are
identity/binding records; they do not by themselves define different model
semantics or prove Host equality. Both normal Host paths use P1 r1.5 here. The
explicit r1.6 comparison contract is a separate, staged revision; compatibility
and a future unordered model representation still need their own evidence.


The detailed timing schema `spireagent/managed-detail-seconds-v1` adds nested
launch/reset, Runtime startup, runtime publication, evidence publication, peer
copy and full peer readback costs. Do not add nested details to lifecycle totals.
Host rc46 also accepts an exact-episode, **manager-only** `performance` command
with `expected_runtime_instance_id` and `expected_game_continuity_id`. It reads
existing `ManagedPlayerEnvironmentSession.performance()` counters and native
`process_metrics`; it neither advances the game nor changes the Agent surface.
The evaluation configuration `measure_host_performance: true` records before and
after snapshots in private attempt artifacts. Counter differences attribute Host
projection/native transport work; native process CPU is not pure simulation wall
time, and nested stage counters must not be summed as disjoint costs. Older
frozen packages do not advertise this diagnostic and are not silently upgraded.

Runtime rc52's Managed settling watchdog bounds a repeated snapshot wait. The
application defaults to 120,000 ms and retains the episode as unknown with reason
`managed_settling_stalled`; exact original evidence and accepted Host shutdown
remain separate facts. M051's original offer is never reissued. M2a located the
missing exact Godot logarithm binding and verified the original three native turns
plus one separate new full-seed validation slot (natural loss at floor17, no
unknown, complete typed R2 readback). This closes that counterexample, not all
possible native waits or full-game equivalence.

M2a's explicit r1.7 path implements only the two user-approved public remainders
(KUSARIGAMA/LASTING_CANDY). Both Hosts use the shared read-only Native Foundation
seam at the original capture boundary, with PB3 snapshot/session/exact-game
witnesses. See the versioned P1 section above for fields, legacy ambiguity and
opt-in commands. Raw display counters and default PB1/PB2/P1 r1.5 remain unchanged.
The pure JungleMazeAdventure debug audio call is separately remapped only when
Managed TestMode has no audio singleton; native GainGold hooks and finish remain.
All replaced seams and their exact native regressions are in the existing manifest.
