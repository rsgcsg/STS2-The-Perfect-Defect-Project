## 1. 第一阶段的三个交付

| 工作 | 应交付什么 | 完成标准 |
|---|---|---|
| 研究入口与设计对齐 | 模型家族、横轴、阶段问题、历史映射、结论及归档规则 | 当前重点与历史证据可查；设计、实现、实测明确区分 |
| 数据与公共合同 | 决策／来源／成员索引、固定分配、隔离协议、归档规则、模型产物合同及必要 UI | 能固定一份真实小样，逐条查到来源、版本、用途和使用关系 |
| S01 最小完整路径 | 准备输入、训练 Linear 头、保存、跨进程恢复、导出、开发侧评测、目标机器加载与新输入评分 | 一个真实小样模型走完链路，产生可追溯报告和成本记录 |

第一阶段不要求完成 S02–S12、整批一万条训练、Z/O、LoRA、循环记忆、RL、
真实 Gold 科学评测、自动游戏执行或完整通关。全模型通用插件框架也不是前置条件。
公共接口保留后续扩展位置，但不为未实现的模型提供假运行入口。

“一万条”是后续 S0 共享候选池目标，不是第一阶段最低训练数量，也不是一万局。
原始条数、唯一决策、准入数、局／战斗数、目标覆盖分别盘点。先做 50–100 条 train 小样；
开发侧评测使用单独保留的 dev 数据，不取 test／Gold 调试。代表性性能样本另按实际长度、
候选数和支持 surface 覆盖，可从 train 内扩大至数百条，不事先保证数据资格或可用数量。

第一阶段不通过“训练集上 loss 下降”一项验收：必须同时有真实输入身份、恢复、独立 dev、
导出、目标机器新输入评分与缺项报告。小样效果只用于工程检查，不能宣布模型强弱。

## 2. S01 / A1 的确切含义

本轮用户口中的 A1 按 S01 / S0-L 理解；不新增 A1 实验 ID，也不与旧在线适配器 S1 混称。

```text
当前允许观察 O + 每个真实候选 a_i
    → 同一冻结 Qwen3-0.6B-Base，分别联合编码
    → masked mean，1024 维
    → Linear(1024, 1)
    → 全部候选的分数
```

Qwen pin、tokenizer、serializer、pooling、完整候选映射和允许 Reads 都进入产物身份。
参考权重 revision 为 `da87bfb608c14b7cf20ba1ce41287e8de496c0cd`；实际下载要校验固定身份。
用人类选择计算候选上的交叉熵 N，只更新 Linear；没有 Z/O、记忆或语言生成。
有 bias 时该头是 1025 个参数；共享标量 bias 在 softmax 排序中抵消，不因此宣称额外表达力。
Qwen 的编码计算仍是主要成本，不能只数评分头。

训练可预计算固定特征，再在 CPU 上训练头。在线处理新局面仍须运行 Qwen；
在已有缓存向量上打分不算目标机器新输入推理通过。
现有 RankingEngine 默认单决策更新，第一阶段可沿用并显式记录该协议。
后续若采用 S0 十二格的有效 batch32、5 epochs 配方，另立固定 TrainSpec；
不能把这次短小样运行重新标成该完整协议的已完成结果。

## 4. 实际交付顺序

1. 对照当前合同确定 source、decision、dataset member、allocation、model 的身份与引用。
   新协议走 owning schema/version 与消费者回归；历史格式及隔离规则不能被默默重新解释。
2. 盘点来源；固定小样成员和 dev，保存协议、种子、质量版本及排除解释。
   不完整局保留真实状态；是否进入当前决策 loader 由证据资格决定。
3. 用 synthetic 验证身份、隔离、Gold、归档、恢复等故障路径；其产物与真实人类数据分离。
4. 尽早用工程输入探测目标机器加载和完整编码路径，再准备真 Qwen 特征；不能批量编码后才发现无法导出。
5. S01 小样训练；在明确更新边界保存 checkpoint，退出进程后恢复，验证数据／参数／步数对应。
   新增梯度累积时另外验证中途状态，不直接套用旧恢复保证。
6. dev 评测与报告；保存候选指标、失败、耗时与来源。导出固定模型包。
7. 目标机器对新的允许输入评分，核对候选对齐、分数与排序差异、延迟、内存和重复运行稳定性。
8. 通过公共服务接入云端／本地控制台，复验切页、恢复访问、归档与反向追踪；报告剩余缺项。

Gold 先用独立 synthetic 封存 fixture 检查拒绝路径；真实 Gold 不用于这轮排错。
如需一个有界云任务验收，必须先核对具体预算授权与实际余额；仅有月赠额度不等于可以消费。
本阶段完成不依赖游戏内 Human 操作；shadow／受控执行属于后续单独记录的运行证据。

## 5. 部署验收针对选定目标机器

目标可以是 Linux/CUDA、Windows、Mac/CPU/MPS 或授权的云机器；第一阶段只要求一个
明确环境完成真实权重加载和新输入编码／评分。训练与推理可在同一机器或不同机器。
不因用户有 Mac 而强制先实现 MPS，不从某平台通过推断其他平台也通过。

产物绑定 graph、权重、tokenizer、serializer、pooling、dtype、后端及支持范围。
在独立进程加载，不依赖训练进程内存或未登记临时文件。完整返回所有候选，不能为了
速度删候选或静默截断输入。缓存头评分不等于新输入推理。报告加载耗时、温机后
p50/p95、峰值内存、失败及设备间数值差异，近并列排序变化单独记录。

当前 RealQwenBackend 的科学 v0 合同仍是 CUDA/BF16。其他后端须有独立、明确的
工程身份与兼容性检查，不能为运行小样而删除历史资格限制。若选 Mac，则先验证
算子、dtype 与实际吞吐；此前 M4/16 GiB 和基础 MPS 运算检查不等于 Qwen 已验收。

第一阶段不要求启动游戏。新输入可来自合法录制投影；评分、原生 shadow、真实执行
与科学策略质量是不同证据。游戏同机资源竞争和真实控制留给后续阶段。

## 6. 第一阶段如何计成本

分开报告工程开发成本、本机时间和云账单，不把“头训练很便宜”解释成整项工程便宜。

- CPU 工作：核验、索引、数据选择、小头训练、报告、序列目标库存统计。
- Qwen 工作：固定输入编码与新输入推理；第一次模型准备与后续热运行分别计。
- 存储：原始证据、成员清单、固定特征、checkpoint；可复用缓存不重复准备。
- 云：先核实余额／授权上限，再提交有界任务；计入 CPU、主存、启动、保存、失败与重试。

第一阶段的计划最多先为代表性 GPU profile 预留原 30 美元情景中的 3 美元，
不是新增预算授权，也不是承诺第一阶段全部花费只有 3 美元。本地可完成的工作不为演示而上 GPU。
十二配置的完整费用必须用实测吞吐重新算；本阶段不承担十二配置 5 epochs 的资源承诺。
普通 Functions 价格与用量规则以[Modal 定价](https://modal.com/pricing)、
[资源计费](https://modal.com/docs/guide/resources)、[预算](https://modal.com/docs/guide/budgets)为准；
不把赠送额度当实际剩余，也不把小时 timeout 当美元上限。

## 7. 后续十二配置保留，但不属于第一阶段完成条件

S0 pilot 清单沿用 `stpd.s0.pipeline-10k.v2`；阶段拆分不修改已存在实验的含义。
全部 M0、R0，每配置先一个 seed；同主体的变体分别计运行。

| ID | 主体与骨干 | 目标 | 对照 |
|---|---|---|---|
| S01 | A／PF，Linear | N | 本阶段实现小样路径；完整 pilot 运行另计 |
| S02 | A／PF，MLP | N | S01：读出头 |
| S03 | D-Simple／PF | N | 共享当前向量＋MLP 更新 |
| S04 | 单主干 B／PF | N | 动作末尾可训练读出 |
| S05 | D-Simple／S | N | S03：从头小模型系统 |
| S06 | 单主干 B／S | N | S04：从头小模型系统 |
| S07 | D-Simple／RF | N | S03：随机冻结 Qwen |
| S08 | 单主干 B／RF | N | S04：随机冻结 Qwen |
| S09 | D-Simple／PF | N＋Z-latent-fixed | S03：真实下一步辅助 |
| S10 | B/C1／PF | N＋Z-latent-fixed | S04：同图增加后继辅助 |
| S11 | D-Simple／PF | N＋O-chain.v1 | S03：结果目标包 |
| S12 | 单主干 B／PF | N＋O-chain.v1 | S04：结果目标包 |

PF=预训练冻结；RF=同配置随机初始化后冻结，不是打乱文本；S=自有 tokenizer／小主干从头训练。
B/C 始终一个 Transformer 主干；可训练 query 要穿过冻结主干传梯度，不能将最终表示永久缓存。
D-Simple 是向量＋MLP，不是双 decoder D1。两个 S 不用 Qwen 权重、tokenizer 或 teacher。
Z 只监督真实执行且后继准入的分支；O 包含胜利、真实失败层数、战斗末 HP、剩余主动出牌数
和战斗终点 latent，各项有独立 mask，不是无条件“血多／牌少就是好”的奖励，也不是 TD/RL。

配方沿[总纲](MODEL_DESIGN.zh-CN.md)：A 为 masked mean 1024；D-Simple 的更新 MLP
2048→1024→1024、评分 1024→256→1；B 用末尾 soft ACT_READOUT＋Linear。
S 用 train-only BPE8192、d384、2层／6 heads／FFN1536 的 Pre-LN 小主干；B 为因果分支，
D 的状态和动作共享 E。两个 S 共用 tokenizer 身份；PF/RF 对照匹配新增模块初值。
Z 共用固定 Qwen teacher 的归一化1024摘要、q(d→256→1024)和余弦目标；对应 N 保留匹配辅助头、
系数为零。O 按真实局／战斗平衡，与下一步 Z 独立记账，目标详情由总纲维护。

完整 pilot 暂定 seed1701、5 epochs、有效batch32（须先扩展现有 runner）、AdamW／wd0.01／clip1；
A head lr1e-3，其余新增模块或 S 主干 lr3e-4，辅助权重按总纲。可行性阶段修订须固定新协议。
12个配置×1seed=12次计划完整运行；补到3seeds为36次。暂停恢复不是新增seed，失败重试单独计成本。
A两格、D五格、B五格；随机参考不训练。后续按4＋4＋4推进，但本阶段先停在S01最小闭环。
更远的 P01–P22／66次属于研究路线，不自动扣除或冒用本阶段工程结果。

## 8. 阶段验收与交付

- 固定真实小样和 dev；有 source/decision/member/allocation ID，能正向／反向定位。
- 所选普通隔离协议执行一致；Gold及真实身份不被设置开关绕过；缺失边界不假报通过。
- 阶段相关对象支持归档／恢复；老实验的引用、Gold和质量账不随归档消失。
- S01有真实输入特征、有限训练结果、跨进程恢复、固定模型包和开发侧评测报告。
- 目标机器对新输入完成完整Qwen＋Linear评分；实际性能和失败如实报告，不能仅测缓存头。
- 云端／本地调用同一服务；进度切页保持，重复提交与未知状态不产生无界付费重跑。
- 报告准确区分接口测试、小样训练、目标机器加载／评分和尚未完成的原生／科学项。

软件改动经正常 topic PR 与受影响检查交付；只有需更新运行服务时才按 owner runbook 发布。
按每项实际变更保留回滚方式；研究改动不自动要求重编 Mod、重启 Hub 或升级采集器。

## 9. 实施顺序与扩展要求

先公共代码／合同与 CLI，再真实小样验收，最后将必要 UI 接到同一服务。
允许整理重复逻辑和错误接缝，以好用、可恢复、可追踪为目标；保留有效实现和历史
消费者，不按理想目录新建空框架。已有 ArtifactStore、Registry、Reporter、Worker
继续使用。未来 token／sequence runner 是不同执行能力，不强迫塞进 pooled runner。

阶段优先序：研究入口对齐 → 精确来源及固定分配 → 统一输入与执行入口 → S01 训练／
恢复／dev／导出 → 指定机器推理 → 最小 UI 与归档／成本报告。
小样真实训练与约一万条管理容量检查分别验收；规模不足时报告实际数量。

先复用索引、分片和可靠缓存，逐步记录冷／热路径、读写量、峰值内存、失败及恢复重做量。
不能通过跳过数据身份／Gold 检查获得性能。配置含数据、模型和运行环境身份；网页、
CLI、Worker 共享 owner 接口。公共服务不依赖 UI，不增加第二套成员／用途账。

研究阶段与结论原则见 [研究路线与历史维护](RESEARCH_ROADMAP.zh-CN.md)。

实施入口及命令语义见 [S01 工作流](S01_WORKFLOW.md)，新增合同见 [ADR-0011](../../../docs/adr/0011-fixed-decision-allocation-and-portable-s01.md)。
