# 本机录制、数据集和小 B 训练

本页描述当前源码候选的操作流程。工作台须启用包含这些功能的版本；
已启用版本和验收状态以 [CURRENT](../../../docs/memory/CURRENT.md) 为准，
不能从本页推断当前运行服务已经更新。

这条路径用于把工程流程跑通。它不要求登录，不启动云端资源，不加载游戏模型。
训练得到的模型出现在本机资料中，并不代表它已装入 Runtime 或学会了打游戏。

## 日常只需要做什么

1. 从游戏 Mod 打开工作台，进入本机资料，确认录制已经结束并导入。
2. 选择要使用的录制，预览后保存一份训练数据集。数据集只记录选了哪些来源；
   不会复制一套原始录制，也不会移动旧资料。
3. 打开训练数据集，明确点击开始本机短训练。当前是固定的 CPU 小 B 三步工程小样，
   不是后台自动训练，也不是完整实验。页面刷新只查看状态。
4. 完成后打开结果、模型或开发集报告。它们互相链接到本次确切对象。
   模型概览只显示记录中能够相互核对的配方、骨干和步数。
5. 对支持的本机小 B 模型，在详情页明确点击“导出并校验”。服务会导出到
   本机受控目录并用独立评分器加载检查；不要求登录，不要求游戏正在运行。
   页面只显示结果和大小，不要求寻找权重路径。

## 导出成功不等于已经能在游戏里运行

“导出并校验”只检查模型产物能否按自己的输入格式装入评分器。它不会登记
游戏策略、切换模式、接管游戏或开始训练。第一批只接当前文字菜单格式的
CPU 小 B 从头模型；不隐式下载 Qwen 或启动其他 GPU 后端。

下一步登记仍要核对当前 Connector、游戏和 Modset 身份，以及明确的场景支持范围。
游戏不在时可以完成离线导出，不能拿旧录制或模型内的历史身份代替当前环境。
重复点击不能并发导出；中断后显示真实状态，不自动重新开始。

## 两种样本保留各自含义

- **完整决策**：已有公开观察、动作和相应证据的决策路径。使用原来的完整决策数据集入口。
- **操作标签**：记录真人在当前文字页面选择了哪个输入。可用于模仿该输入选择，
  但不能补成“游戏已执行成功”，也不能补出后继状态、奖励或完整轨迹。

一份录制可能同时提供两种样本；计数不能相加当成更多完整决策。
操作标签数据集保存的是 Human SOURCE，训练用途另由同一资料库的用途记录确认。
它不是第二个资料库，也不需要把标签复制成完整决策格式。
当前操作标签入口只登记训练用途；它没有新增 Human 测试或 Gold 发布入口。

## 为什么可以保存，但暂时不能训练

保存数据集和得到有效训练/开发划分是两回事。当前操作标签短训练最多接受
32 条训练样本和 8 条开发样本；超过上限会明确拒绝，不偷偷删减。数据集仍可保留。
当前 Human v2 协议按录制分组，
并把出现相同可见页面及动作菜单的组连在一起，避免同样输入跨训练与开发集。
共享页面可能把很多录制连成一组；所以增加录制数量不保证能够满足划分条件。
分组不足会在训练输入准备时说明原因，不会把重复数据任意拆开来制造独立评估。

即使有多个录制分组，也不等于已经证明它们来自独立游戏局。Human 报告将这项
资格保持为未知；没有独立局置信区间，不把高准确率直接称为模型质量达标。
未来采用不同划分方法时，应发布明确的新协议，保留旧来源、用途和结果身份。

## 出错或中断时

- 等待中的创建/训练不能重复开始；刷新只查状态，不自动补发命令。
- 若创建结果尚未确认，先核对上次结果；不要用新建数据集掩盖不明结果。
- 模型和报告保留原结果。失败记录不抹掉，旧数据和已登记用途也不会被覆盖。
- 普通训练不会要求把未知旧历史说成 Gold。Gold 保留额外的用途隔离条件。

## 工程边界

默认小 B 对候选数的评分成本在固定输入长度下线性增长；不是承诺总 token 运算量线性。
三步 CPU 训练是操作流程小样。当前入口不下载 Qwen、不调用云训练、不自动导出或接管游戏。
实际机器耗时以本次任务记录为准，不能用合成小样时间估算一万条真实数据的成本。
