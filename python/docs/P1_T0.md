# P1 M-std local engineering slice

This is the authorized data-consumer → Input/Target → CPU training → Model →
stateless Agent path on `p1-global-r1`. It consumes current r1.4 optional segments;
it does not change the environment protocol, producer, Mod or recording. It
implements the selected Q3 M-std: two width-128 text Transformer layers, three
width-192/four-head scene layers, dropout 0.1, 10% symbolic-ID masking, one action
cross-attention layer and listwise N loss over the complete legal catalog. There
are no O weights, memory or auxiliary heads. Parameter count is approximately
4.4 million and is measured in the run's `lengths.json`.

## Input, targets and provenance

`stpd.p1.data.read_segments` binds the actual source checksum, current revision,
branch, complete start boundary and exact unique catalog chosen. `next` never
crosses a segment; `end` requires an observed terminal on that same branch.
Targets and source metadata are never added to the current model observation.
The producer's protocol state stays in the immutable source; model reset is
independently stateless at every observation. Fifteen segments from one source
run receive one train-only engineering lineage, with no manufactured holdout.

`stpd.p1.input.project` follows SDK `modelView` by excluding the transport envelope.
It represents public dictionaries/lists, field values and parent/reference
relations, including reference-only identities without manufacturing bodies.
Dictionary key order is canonical, list positions remain explicit and repeated
public aliases connect all their occurrences. Definition IDs use separate typed
embeddings; their spelling does not bypass ID masking through the text encoder.
Null numeric fields have an explicit missing marker. Text numbers become `<NUM>`
plus signed-log numerical encodings. No token, entity or candidate truncation is
performed. The byte-level BPE vocabulary is fitted only on the selected training
descriptions, with a 4096-token capacity; actual vocabulary size is recorded.

Historical r1.2/r1.3 trajectories and the r1.4 trajectory wrapper are not accepted
as current segment training inputs. Use them only for explicitly scoped metadata
compatibility/projection regressions. Do not fill fields or relabel revisions.

## Run and restore

Use an existing Python 3.11 environment containing the locked project ML/local
model dependencies. In `python/`, with the current component Evidence dependency
available, run:

```sh
python -m stpd.p1.t0 run --source /ABS/current-segments.json \
  --producer-receipt /ABS/current-segments-receipt.json --out /ABS/new-run --steps 4
```

The command starts no network, worker service or game. It copies/verifies the
source, fixes vocabulary and sampling, and runs a bounded 2–32 CPU update plan.
Effective batch remains 64; CPU execution accumulates one complete observation
at a time on two threads. AdamW, learning rate 3e-4, weight decay 0.01, 5% warmup
and cosine decay follow the selected recipe. This engineering plan has no dev
early stopping or strategy-quality claim.

Checkpoint serialization reuses `stpd.workers.checkpoint_codec`. It stores model,
optimizer, used Torch/Python RNG states, sampler generator/permutation/cursor,
epoch, step, history and exact execution identity. A fresh process resumes the
midpoint with identical following batches. The final proof compares all state
against uninterrupted CPU execution with declared zero tolerance. Actual
parameter and same-observation score changes are checked independently of loss.

The detached `export/` contains a checksum-bound tensor-tree model and provenance
descriptor. Loading uses the trusted architecture/InputSpec and exact parameter
shapes; model content never chooses executable code.

## Private installation and existing Runtime

The environment owner supplies an exact current P1 Agent manifest envelope for
the chosen candidate. After that binding, create a **new private** registration:

```sh
python -m stpd.p1.t0 register --export /ABS/run/export \
  --environment-manifest /ABS/owner-p1-environment.json --out /ABS/private/models
```

This copies the model into the private directory, preserving the original. It
does not modify shipped registrations, active model selection, Runtime install
or environment identity. For the workbench, use a private ProjectConfig whose
`state_dir/models` is this directory. `LocalModelService` trusts only the added
`stpd-p1-mstd-agent` code owner and retains the existing program adapter checks.

The adapter launch arguments are:

```sh
python -m stpd.p1.agent --config /ABS/private/models/config.json \
  --manifest /ABS/private/models/manifest.json --binding-root /ABS/private/models
```

The **existing Policy Runtime** supervises this process. The adapter consumes
full current observation/catalog, acknowledges consumption and returns the
existing handle choice ID plus catalog-bound scores. Runtime retains lowering,
native operands, execution, Stop, unknown-delivery handling and control release.
Empty recovery model bindings mean no recurrent state; the immutable model
dependency remains declared by artifact, installation and AgentComposition.

No adapter-only command grants a Reference window. The main lane must allocate
an exclusive candidate/window and bind the actual environment before gameplay.
Stop through the existing Runtime/workbench control; do not kill the game or
retry an unknown delivery.

## Checks and evidence limits

`tests/test_p1_t0.py` covers mask/branch/boundary counterexamples, ID-mask and key
order fidelity, complete text, controlled-weight legal scoring, exact model load,
checkpoint continuation and invalid-install blocked behavior. The local opt-in
`components/policy-runtime/test/p1-model-integration.test.ts` uses
`STPD_T0_MODEL_EXPORT`, `STPD_TEST_PYTHON` and optional `STPD_T0_PROOF_DIR` to run a
real trained package through the production Runtime and a synthetic HTTP Host.
That check proves the port/Receipt/terminal/control-release connection, not a
Reference game or strategy result. Real gameplay remains T0b after allocation.
